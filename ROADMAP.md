# Parkoreen mechanics and 2D engine roadmap

Parkoreen should grow from a parkour map editor into a creator-friendly 2D game engine. The mechanics editor and plugins are the bridge between those stages. This roadmap keeps the existing parkour workflow usable while making that foundation reliable enough to extend.

## Phase 1: make the current foundation dependable

- Keep map mechanics data stable across save/load, including triggers, events, and variables, and migrate older action data without dropping it. A shared map-data normalizer now merges distinct legacy `actions` records with canonical `events`, prefers canonical records for duplicate IDs, preserves repeated canonical records that lack IDs, and assigns deterministic repair IDs to malformed legacy records while reserving valid IDs elsewhere in the list. Matching ID-less legacy copies are merged against canonical records without removing extra legacy records. Separate loads of the same save preserve event links without a generated ID stealing a later record's identity. The room worker uses the same canonical-first ID rule when routing guest event requests, and every app page that deserializes map exports loads this normalizer before `exportImport.js`. The Mechanics Editor keeps unknown action records opaque through edit, reorder, and save, preserves unknown trigger types and their config while maintaining their Event link, and lets authors save unrelated edits to variables with unknown scalar/List value types without coercing those values.
- Make trigger state explicit per map, player, and trigger. Ensure game-start, game-end, player-death, room join/leave, zone, input, timer, button, jump, respawn, landing, and attack-hit events fire according to their documented edge or repeat behavior. The editor and runtime now reject malformed trigger types, key combinations, Player Stats conditions, and Repeat intervals; legacy timed-action defaults are explicit in both editor and runtime. Repeat intervals now convert ticks, seconds, and minutes to runtime cadence correctly, Player Stats reads the account username and room role, room lifecycle events run once on the host, `player.jumped` emits a Player Jumps event only after a successful core or plugin jump, `player.land` fires only on actual floor contact, Player Lands exposes its surface to event code, Player Respawns fires after plugin reset hooks, Game Ends fires once after successful endpoint completion with elapsed-time and test-run context, and Player Dies fires once from the shared death boundary with its source. Hosted Mechanics revision counters now require safe integers on both sides of the room protocol. The Hollow Knight plugin now reports each map object hit once per nail swing, and Mechanics can link a selected object's hit to an Event. This trigger is client-local in hosted rooms. The zone picker now lists enabled named zone groups once, matching runtime enter/leave behavior when several regions share a name. Tilemap trigger validation now matches runtime one-way contact semantics for ramps and one-way polygons.
- Give events a supported runtime API for reading and changing game state. Python event code now has a versioned `parkoreen` API for read-only event/player context (including movement state), bounded paged snapshots of locally visible players, objects and native tilemap/cells, Player-variable and Player-List reads plus host-published writes by live player id, validated object enabled/position changes and tilemap cell behavior changes, bounded local player velocity changes, typed variable/List access, and local messages; broader game APIs and host-validated multiplayer scripting remain future work.
- Report unresolved runtime trigger references with the originating trigger id. Zone enter/leave, object touch, and tilemap touch now report absent or disabled targets to the Mechanics runtime error history once until fixed instead of silently staying inactive or repeating the same error every frame.
- Keep device-specific editor, settings, gameplay HUD, and controls selected from device capabilities rather than a saved touchscreen preference. Hybrid devices now follow their most recently used pointer or physical keyboard, and mobile editor toolbars and overlays account for touch controls and safe areas.
- Fix Hollow Knight down-slash pogo so collision, bounce velocity, and the following physics step agree; pogo now recognizes enabled solid blocks and collidable tilemap cells (including ramps and polygons) from above as well as spikes and Soul Statues. The first-contact check uses the player's ground collider, requires non-upward movement, and tests the projected fall step rather than the long nail hitbox for solid surfaces, while rejecting hits from below. On a projected platform contact, the plugin aligns the player's feet with the surface before applying rebound velocity, so the skipped fall step cannot become an early midair bounce and overlap resolution cannot erase the rebound. Add readable, configurable hit, charge, dash, and heal effects, including a traveling nail-slash highlight. The editor exposes per-map pogo bounce strength, effect visibility and colors, plus camera shake toggles and hit/landing intensity. Landing dust and hit/landing/Super Dash impact shake use lifecycle hooks. Pogo contacts now add a short upward rebound flare controlled by the impact-effects setting. A bounded `render.camera` hook exposes frame-local shake offsets without changing camera tracking.
- The player-facing “Wiki” is now the Parkoreen Guide; public labels explain that it is maintained reference content players cannot edit, while existing `/wiki/` links continue to work.
- Version plugin manifests and document the current trusted, built-in plugin workflow.

## Phase 2: build a useful mechanics system

- Campaign-scoped scalar Variables and Lists share state across maps through stable author-defined keys, work through declarative Events and the Python Event API, support typed add/remove/clear/contains operations, and save in the current browser account for solo play; cloud and cross-device save synchronization remain future work.

- Define a small action catalog first: set/add/calculate variable, branch on condition or connected-player count, enable/disable a trigger or object, set/damage object health, move/teleport player or map object, set player checkpoint, change player health, show text, play sound, spawn/remove temporary object instances, start/stop timer, and emit an event. Calculate Number Variable supports add, subtract, multiply, and divide while validating integer results and rejecting division by zero. Object health now targets a selected or touched map object, disables it at zero, offers an optional defeat Event, and exposes health in Event Python context. Supported shared triggers synchronize the host's health state; HK nail-hit triggers remain local because the Worker does not validate attack geometry. Set Trigger Enabled now changes a trigger for the current session, supports re-enabling map-authored disabled triggers, resets with the session, and synchronizes through host-validated room state. Teleport Player can use explicit coordinates or place the player above an authored map object. Map objects now support immediate position changes, bounded eased movement, and up to 64 temporary copies of authored templates from event actions; copies can expire after a bounded lifetime, touch triggers can target them, and the room host shares their template ids, positions, and tags. Solid ground carries a player standing on it during movement. Player-count branches use typed per-player variables and host-authoritative room state.
- Give actions typed inputs, validation, predictable execution order, per-map state, and error reporting. Player teleports are bounded to ±10,000,000 map pixels and velocity components to ±10,000; the editor and runtime apply the same limits. Integer values use JavaScript's safe-integer range consistently for defaults, actions, conditions, typed List items, arithmetic, and local saves. List variables support bounded typed add/remove/clear and contains-branch actions with optional local persistence and host-synchronized room state; a full List reports a rate-limited author error when an add is attempted. Player-scoped Lists support triggering/touched-player targets, host-published room snapshots, local solo saves, and Python List reads/writes. Object Health supports set, damage, defeat Events, and health-condition branches for enemy phases and health-gated interactions. Python runs yield cooperatively about every 8 ms, stop after a 100 ms execution budget, and cannot open blocking `input()` prompts; declarative timers are bounded. Add explicit cancellation and author-facing errors for any future wait/async actions.
- Make room-specific physics configurable in Events. Set Gravity (0–5), Set Jump Force (-100 to -0.1), Set Player Speed (0.1–100), and Set Movement Control (horizontal acceleration, air control, and terminal fall speed) now override Map Config for the session, synchronize through host-validated room state, affect core and Hollow Knight movement, and restore on reset without changing saved map settings.
- Let Mechanics change object visuals as gameplay state changes. Set Object Sprite Frame can hold a sprite-sheet object on any configured frame; Play Object Sprite Animation plays a bounded frame range or a named clip at a selected rate and can loop or hold its final frame, with an optional completion Event for one-shot playback; Set Object Opacity can fade it without changing collision. Up to 32 named clips can be authored per object sheet and reused across Events. These overrides use bounded host-validated synchronization and restore authored appearance on reset.
- Bridge plugin controls into mechanics: Player Action Input now lists controls declared by enabled plugins and fires once on each press. These custom-control events are local in multiplayer; shared state changes still require a supported host-validated trigger path.
- Events can play a named sound declared by an enabled plugin with bounded volume, through the plugin audio manager rather than a saved asset URL. Playback follows the client executing the Event and is not broadcast to other players.
- Events can also stop declared plugin sounds, including randomized sound groups, so authors can end plugin audio on scene, dash, or round transitions.
- Runtime action and Python failures now populate a bounded recent-error history per map; malformed or unsupported imported action records include their Event and action position. Missing or disabled Events linked from triggers and timers, plus recursive and over-limit action links, are also reported. Runtime link diagnostics identify the originating trigger or Event so the Mechanics dashboard can open that block directly. Item-use actions validate their required success route and configured failure route before mutating inventory. Test Game shows a rate-limited notice, and the Mechanics dashboard can clear the history. Ordinary player sessions do not show author diagnostics.
- Improve the editor from a list of disconnected trigger/event records into linked flows. Cards expose clickable links, and the new Flow map draws trigger, event, and variable nodes with connections for linked triggers, event calls, branches, timers, and variable use. The dashboard also reports invalid values, recursive event chains, unreachable events, timer-linked event cycles, and synchronous paths that may exceed runtime nesting or action-chain limits; richer path-feasibility analysis remains future work.
- Ship reusable templates for checkpoints, timed courses, hide-and-seek, tag, switches, doors, inventory, and round-based games. The editor now has additive Timed Round, Player Inventory with optional touch Button access, pickup-object collection, and solo local-save opt-in, Tag, Hide And Seek with automatic last-hider completion, a zone-bound shared Timed Course, a button/object-bound Switch And Door, a zone-bound Checkpoint flow, and a button-bound Save Point that uses the map's optional remembered-checkpoint save. Maps can opt into remembering the latest checkpoint, single-value map/player variables can opt into browser-local save data, and Set Object Enabled actions can opt into solo object-state persistence. Set Object Position and bounded eased Move Object actions now synchronize positions and motion paths through the multiplayer host. Cross-device/cloud save slots and broader save/respawn/win-state patterns remain future work.
- Define deterministic reset behavior for playtesting, respawn, rounds, and map reloads. Map-scoped and per-player variables have separate local runtime storage, with optional per-account browser saves for selected values; the host publishes validated per-player snapshots. Shared timer callbacks now preserve the initiating player id for delayed per-player actions. Validated player/gameplay actions still need server authority.
- Extend the room-authoritative mechanics slice through the multiplayer backend. The host validates and publishes map-variable, per-player-variable, trigger-enabled, object-enabled, object-position, and bounded object-motion snapshots. The Worker checks zone entry/leave transitions, object and named-button contact, touch-other-player contact, key combinations, and Map/Player Variable conditions before forwarding guest event requests; it derives contacted ids and validates variable conditions against host-synced state, including dynamic trigger-enabled state. For supported guest trigger flows, the host replays the linked Event in order, evaluates its declarative branches, and records enabled routes only when replay reaches Show Choices or Show Menu; the Worker verifies a selected Event is declared by that parent, and the host accepts it only against its own pending route record. Choice prompts and selections remain local to each player. Contact requests latch until separation. Unsupported guest trigger types are rejected. Movement, keyboard samples, and the time at which a guest reports them remain client-reported; physics and input are not server-simulated, so hosted mechanics still are not cheat-resistant.

## Phase 3: add 2D game-authoring capabilities

- Map objects and the player now support uploaded PNG/JPEG/WebP sprite sheets with row-major frame playback (up to 256 frames, 30 FPS, 1 MB per image, and 8 MB of serialized map assets). Player sheets can define idle, run, jump, and fall rows, plus optional Attack, Hurt, and Dash rows selected from shared plugin player states; Attack plays once and the other action rows loop while active. Collision behavior stays independent from the artwork, and older four-row sheets keep working. Map and player sheets persist through map save/load and `.pkrn` media-file round trips; object sheets also persist in Object Stamps. Tilemaps now accept bounded per-layer PNG/JPEG/WebP atlases with frame selection and up to eight animation frames per painted cell; large-map streaming remains future work.

- Add scenes and transitions, camera bounds/follow modes, layers, tilemaps, and reusable prefabs. Solo Play and Test can now transition to another saved map through a validated, terminal Mechanics action; each destination initializes its plugins and Game Starts flow, and stopping a test restores the editor map. Mechanics Events can switch camera follow between both axes, horizontal-only, and vertical-only, then apply custom bounds, disable bounds, or restore Map Config bounds during the current session. Authored camera settings return on reset; these camera actions are local presentation. Multiplayer transitions, authored scene graphs, and linked live-updating prefabs remain future work. The first native tilemap slice adds a 32 px brush, named draw-layer assignment, built-in solid/brick/stone/wood/moss surface textures, solid/one-way/left-rising-ramp/right-rising-ramp/hazard/decorative cell behaviors, bounded compact cell storage, chunk-cache rendering, erasing, and save/load/`.pkrn` persistence. Tilemap cells can cycle through two to eight built-in texture frames or selected atlas frames at 1–12 FPS while retaining authored collision; the runtime bounds animated cells to 2,048 per map and draws them between cached background cells and dynamic objects. Custom per-layer sprite atlases now let creators select a source frame for new 32 px cells; the atlas is bounded, included as a `.pkrn` media file, and independent from collision behavior. Mechanics can trigger on entry to collidable cells in a selected tilemap, filtered by behavior, with host-side overlap checks in hosted rooms; events can change a fixed or touched cell among the built-in behaviors, with host-validated snapshots and reset restoration. Large-map streaming remains future work; tilemap cells now support custom convex polygon collision. Rectangular camera bounds and two-axis, horizontal, or vertical follow modes are configurable per map. Named draw layers can be created on either side of the player and persist through save/load and tile caching; custom layers support independent bounded X/Y parallax in Play and Test, while the editor keeps layers aligned for placement; built-in depths 0/1/2 retain their prior meanings. Object Stamps save and place groups of up to 64 objects, with up to 32 stamps per map; they persist in saves and `.pkrn` files and now transfer across maps as validated, data-only `.pkrstamp` assets.
- Add spritesheets, animation states, collision shapes, and configurable platformer physics. Maps now support bounded horizontal acceleration/braking, an air-control multiplier, and an optional terminal fall speed while preserving existing movement and gravity-scaled falling defaults for older maps. Ground blocks support box and circular solid colliders, capsule colliders with rounded ends along the longer axis, two one-way triangular ramp surfaces, and validated convex polygons with 3–12 normalized vertices; polygon colliders can be one-way top surfaces or fully solid on all sides, with the mode saved and editable. Circular, capsule, and polygon bounds appear in the tester overlay. One-way toggle platforms remain box-only. Player Touches Object triggers use box/circle/capsule overlap geometry; tilemap cells support validated convex polygon colliders with one-way top-surface or fully solid behavior, and local/hosted tilemap contact checks use the polygon bounds.
- Add game-state and UI building blocks for menus, dialogue, inventory, health/soul, checkpoints, enemies, and save points. Mechanics events now have bounded, paged dialogue and 2–8 choice prompts that pause the local player, route to linked events, and resume parent event Python after the selected path; larger option lists scroll within a bounded height on small screens. Show Menu adds a centered, titled, one-shot menu with up to eight Event options, Escape/backdrop dismissal, an optional cancel route, and an optional full solo-simulation pause that also pauses Mechanics timers and excludes pause duration from game elapsed time. A Title Menu template opens at Game Starts; a Pause Menu template wires Escape and an optional touch Button to Resume/Restart. A Player Health Changed trigger reports bounded before/after/delta context, and Show List Panel provides a live local view over Map or Player Lists. String List entries can now render bounded JSON item cards with a name, text icon, description, count, slot, and equipped badge; Set Inventory Item Equipped enforces one equipped card per slot, Branch on Equipped Item routes from that state, and Use Inventory Item consumes a stack or card and routes to a success/failure event. All three support host-synchronized Player Lists. Checkpoint Zone and Button Save Point templates add basic checkpoint flows; open-ended title design and richer save-point UI remain future work.
- Keep authoring responsive on phones and tablets while exposing precise editing tools on computers. Gameplay HUDs and controls must adapt independently from editor layout.
- Use Hollow Knight-style gameplay as a demanding sample project; do not make its mechanics a hard-coded dependency of the engine.

## Phase 4: make plugins authorable by players

- Keep a manifest API version separate from a plugin's display version. Validate ids, dependencies, declared files, and API compatibility. The runtime now uses each release version in declared script and sound URLs so updates invalidate cached plugin assets together.
- Expand the bundled API v1 starter into a plugin SDK with local developer mode, packaging/linting tools, examples, and migration notes in the Guide. A starter scaffolder, schema-linked manifest, configurable render-hook and declared sprite-sheet animation examples, editor type declarations for hooks and API methods, loopback-only local preview for up to eight related unregistered plugins with a per-server token gating discovery, asset delivery, and reload events, plus cache-busted scripts and named declared assets, automatic reload when any selected plugin folder changes, and a manifest-driven plugin library/config editor now exist. Manifest-declared custom controls populate plugin-owned boolean fields on `player.input`, appear in the plugin library, and gain labeled touch buttons on touch-first devices. Core movement control ids are rejected; globally unique plugin controls remain in their own shared input namespace, and runtime discovery plus author preflight report collisions. The built-in action ids reserved for the Hollow Knight plugin remain supported. Manifest/path preflight (including controls, feature flags, object guards, config dependencies, dependency-cycle checks against bundled and sibling plugins, unresolved-dependency warnings, and general assets), non-executing JavaScript syntax checks, cleanup helpers, a bounded ZIP packager with SHA-256 file metadata, a non-extracting package verifier, a hook payload reference, and API/plugin version migration notes are also included. A hook that throws three times consecutively is now removed, its registered cleanup runs, and the plugin card shows the last hook error; load and initialization failures remain visible in the Plugin Library, and maps list missing or failed plugin ids while preserving their saved settings. These diagnostics limit repeated callback failures but do not contain synchronous infinite loops or untrusted code. Deeper static analysis remains future work.
- Plugin preflight now applies the package file-count and byte-size limits before parsing declared JavaScript, so the syntax checker does not read oversized source files before the packager rejects them.
- Define narrow permissions such as map read/write, input, rendering, audio, network, and storage, with a prompt and revocation UI. API v1 now rejects permission declarations in both preflight and runtime discovery, avoiding manifests that imply enforcement the current runtime does not provide.
- Run third-party code in a real isolation boundary with message-based APIs, resource limits, and failure recovery. Do not treat `eval`, `new Function`, or a browser iframe without a threat review as a security sandbox.
- Keep community installation disabled until the isolation, capability, compatibility, and failure-recovery release gates are met. The detailed [plugin security model](assets/plugins/PLUGIN_SECURITY_MODEL.md) defines the trust boundary and acceptance checks; API v1 remains a reviewed, bundled-code workflow.
- A separate [API v2 protocol draft](assets/plugins/PLUGIN_API_V2_DRAFT.md), [JSON Schema](assets/plugins/api-v2-draft/plugin-protocol.schema.json), and [TypeScript declarations](assets/plugins/api-v2-draft/plugin-protocol.d.ts) specify message envelopes, disjoint closed gameplay request variants, per-method result payloads, a paged map snapshot, an initial capability-to-method map, and proposed request/resource limits for future isolated plugins. They are review artifacts only; none of their permissions, limits, or isolation guarantees are enforced yet.
- Add compatibility checks, dependency resolution, signing/review policy for any shared plugin catalog, and export behavior when a map depends on a plugin. The editor now lists map-required plugin ids unavailable in the reviewed local library while preserving their saved configuration, and map import never installs code.

## Current implementation slice

The current slice preserves saved mechanics data across editor, runtime, `.pkrn`, and room event routing, corrects trigger lifecycle behavior (including host-run room join/leave events and local post-restoration player respawns), adds ordered declarative actions, reusable event calls, map and per-player variable branches (including touched-player conditions and connected-player counts), typed Map and Player List add/remove/clear mutations and contains branches with bounded items, optional local List saves, opt-in local persistence for scalar variables, object states, and the latest checkpoint, bounded named timers, bounded temporary object spawning/removal with optional lifetimes, coordinate and object-anchored player teleports, solo saved-map transitions, template-based touch triggers, and host-synchronized instances, additive Player Inventory, Timed Round, Tag, Hide And Seek with automatic round completion, zone-bound Timed Course and Checkpoint, and button/object-bound Switch And Door starter templates, and a Basic HK Enemy template with initialized temporary health, optional timed patrol, and optional contact damage; moving sprite-sheet objects face their horizontal travel direction. Player sprite sheets can optionally add Attack, Hurt, and Dash rows for shared plugin states while four-row locomotion-only maps stay compatible. It syncs validated mechanic snapshots from the room host and adds Worker checks for zone transitions, objects, named buttons, and player contact using recent client-reported positions with derived touch targets and repeat-contact latches. Those samples are not server-simulated physics, so these checks are not cheat-resistant. The slice also provides Python events with a versioned `parkoreen` runtime context for metadata, bounded paged snapshots of locally visible players, objects, and tilemap cells, Player-variable and Player-List reads and host-published writes by live id, typed scalar variables and Map/Player Lists, local messages, host-published List writes, cooperative yields, and a 100 ms execution cap; nearby-object scans for Hollow Knight slashes, checkpoint/endpoint interactions, and immediate button presses now keep stable candidates while hook-dispatched Events query the world, and the plugin includes configurable slash and lateral down-slash impact shards, rebound flares, impact/landing dust, dash-trail, and ability-aura effects. It adds optional per-map camera bounds and axis-specific follow modes for gameplay and testing, named draw layers, native 32 px tilemaps with solid, one-way, damage, and decorative cells, per-layer custom sprite atlases, plus bounded sparse storage and host-synchronized runtime cell-behavior changes, configurable one-way platform blocks, horizontal acceleration and air control with legacy defaults, optional terminal fall speed that also applies to Hollow Knight wall bounces, portable map-scoped Object Stamps using validated `.pkrstamp` assets, replaces the misleading Wiki label with Guide, and provides a bundled API v1 plugin starter with a visible render-hook and sprite-sheet animation example, scaffolder, manifest schema, path preflight for metadata and assets, non-executing JavaScript syntax validation, a bounded transfer package creator with SHA-256 file metadata, a non-extracting package verifier, cleanup helpers, and a hook payload reference. Saves currently stay in the browser and do not sync across devices; object and List persistence is solo-only. Third-party plugin installation remains unavailable until the isolation/permission work in Phase 4 exists.

Dialogue and branching choices are bounded and touch-friendly, pause the local player, yield linked event execution safely, and resume parent Event Python in order; editor validation and the Flow map include choice links. Show Menu adds a centered menu with up to eight Event options, optional cancel routing, Escape/backdrop dismissal, and optional solo-scene pause that also pauses Mechanics timers. Title Menu and Pause Menu templates create reusable entry points, with Pause Menu able to bind an existing touch Button. Show List Panel adds a live, scrollable, local List view for a basic inventory or collection screen; string items can opt into bounded JSON cards with names, text icons, descriptions, counts, slots, and equipped badges; Set Inventory Item Equipped applies one equipped item per slot to a triggering, touched, or all live players; Branch on Equipped Item provides checked true/false Event links for the triggering or touched player; Use Inventory Item consumes a matching card or decrements its stack, then follows success or optional missing-item Event links. Inventory changes use the host-synchronized Player List path in rooms. Show Variable Panel adds a live local view for scalar Map or Player variables, making scores and round/player status visible without custom UI. Checkpoint Zone and Button Save Point templates add zone/button-bound checkpoint flows, with optional same-browser remembered checkpoints for solo play. Custom title flows and cloud save synchronization remain future work.
Player-scoped Lists are a data primitive for per-player collections: Events can add/remove typed items, branch on membership, target triggering/touched/all players, and synchronize host-validated snapshots to every client. Player scope separates state but does not keep values secret in hosted rooms.
The health-change trigger tracks a numeric HP component per player, filters increases or decreases, and passes current, maximum, previous, next, and delta values into Python event context. It remains local because guest-reported health is not authoritative. Game Ends runs locally after endpoint requirements are met, runs once even if collision processing repeats, and exposes elapsed milliseconds and test-run status to Python. Player Dies is emitted only on the first transition to dead, before the automatic respawn step, and exposes the source object or action to local event code.

## Completion criteria

- Every Mechanics Event action in the supported catalog has an editor form/default, runtime execution branch, and `.pkrn`/map save-load round-trip; multiplayer actions declare whether they are host-validated/synchronized or local-only, and unknown imported action records remain intact and visible for repair.
- Object and player sprite sheets reject rows or frame counts outside the whole frames available at their configured frame dimensions; fixed-frame, ranged-animation, and opacity actions save and reload with their Events, render in Play and Test, synchronize validated overrides from the host, and restore the authored frame loop and opacity on reset.
- Named object animation clips validate their unique name, frame range, speed, and loop mode; up to 32 clips survive map save/load, `.pkrn` import/export, and Object Stamp placement, and named-clip Event actions complete and synchronize in solo Play, Test, and hosted rooms.
- Source syntax and manifest checks are supporting evidence only. Completion requires runtime verification of the affected editor, save/load, solo Play/Test, hosted synchronization, reset, and the Hollow Knight pogo paths against the criteria below. `tools/mechanics-roundtrip-runtime-check.html` loads the real World and Code plugin scripts to check trigger/Event/Variable/zone save-load and execution; `tools/hk-pogo-runtime-check.html` checks 13 pogo surfaces plus four rejection cases with the real core and HK plugin scripts.
- A map with triggers, events, and variables saves, reloads, and runs without losing data.
- Ground blocks with box, circle, capsule, either ramp, or a valid convex polygon collider preserve their shape and polygon mode through map save/load and `.pkrn` export/import; capsules collide on every side, ramps and one-way polygons land from above, fully solid polygons also block sides and ceilings, all support appropriate grounding/jumping, and authored bounds appear in the tester overlay. Invalid polygon data is rejected or normalized to the documented default shape.
- The Mechanics dashboard flags invalid scalar defaults, explicit List lengths, and List items, including references to missing, disabled, player-scoped, or List variables; legacy Lists without an explicit length remain editable by inferring the length from their entries.
- Custom draw-layer parallax factors stay within 0–2, survive map save/load and `.pkrn` round-trips, shift layer content at the configured rate in Play and Test, and leave collision and editor placement aligned to world coordinates.
- Tilemap cells save, reload, render on their assigned draw layer, behave as solid/one-way/hazard/decorative, erase cleanly, and round-trip through `.pkrn` files.
- Animated tile cells preserve two-to-eight sanitized built-in texture frames and a bounded frame rate through map save/load and `.pkrn` round-trips; the editor brush supports choosing 2 through 8 frames, and they animate in Play, Test, and the editor while keeping their authored collision behavior, with maps staying within the 2,048-cell animation budget.
- Tilemap atlases accept bounded PNG/JPEG/WebP images with validated frame dimensions and indices, paint the selected atlas frame, preserve each cell's collision behavior, and survive save/load and `.pkrn` media-file round-trips within the combined 8 MiB image-data and 32 megapixel atlas budgets.
- Atlas frame cycles preserve two-to-eight validated frame indices and bounded FPS through map save/load and `.pkrn` round-trips, animate in Play, Test, and the editor, and obey the shared 2,048 animated-cell budget without changing collision behavior.
- Player Touches Tilemap fires on entry to matching collidable cells, rearms after leaving the selected tilemap, exposes the touched cell id to its event, and has hosted overlap checks against saved tile data and recent position samples. Set Tilemap Cell Behavior can change a fixed or touched cell among solid, one-way, hazard, and decorative during play; the host validates and syncs the override, and reset restores authored cells.
- Set Tilemap Cell Behavior remains attached to its Event through map save/load and `.pkrn` import/export; tile behavior overrides are bounded and rejected by the room Worker unless each cell belongs to the saved map.
- Successful endpoint completion fires each enabled Game Ends event exactly once and exposes elapsed milliseconds and test-run status to its event code.
- A fatal hazard, void fall, or Mechanics damage action emits Player Dies once before respawn with source context, including when multiple collisions occur in one update.
- Choice actions save and reload as bounded linked-event data, run the selected enabled event, and resume parent Python after its path completes.
- Show Menu saves and reloads its bounded title, 1–8 unique option labels, enabled Event links, optional cancel Event, and optional solo-world pause; option and cancel routes appear in the Flow map and recursive-path validation, while Escape/backdrop dismissal, bounded small-screen scrolling, keyboard focus containment/restoration, timer and elapsed-time pause accounting, and parent Python continuation behave consistently. Hosted rooms pause only the local player.
- Set Trigger Enabled actions save with their Event, can switch both enabled and authored-disabled triggers during a session, reset with game/mechanics state, synchronize from the host, and are enforced by the Worker when guests request trigger events. Game Ends must evaluate the effective trigger state from the completed session before the next session reset, and a normal reset must publish the empty override state so a hosted room cannot retain stale trigger flags.
- Transition to Map loads a valid saved map in solo Play or Test, starts its Game Starts triggers and plugins, ends the current event chain, and restores the original editor scene when a test run stops.
- Restart Scene reloads the active saved scene or resets an unsaved scene in solo Play or Test, uses the remembered checkpoint when enabled in solo Play and the Spawn Point/default start in Test, resets scene-local Mechanics state, runs Game Starts once, and ends the current event chain. It is rejected in multiplayer.
- Pause Menu template installs an Escape-key trigger and Resume/Restart menu, pauses solo simulation and Mechanics timers, and adds a touch-friendly trigger when an existing Button is selected; every generated link is valid and unique, both access paths open the same local menu, and duplicate Escape-triggered overlays are prevented. Hosted rooms pause only the local player.
- Title Menu template links a Game Starts trigger to a one-option Show Menu and a Start Event; the menu pauses solo simulation until selected, routes validly after save/load, and duplicate Game Starts menu flows are prevented.
- A Transition to Map action inside Game Ends resumes the run in the next scene; if destination loading fails, the normal completion screen still appears.
- Show List Panel reads the selected Map List or triggering player's Player List, refreshes when its contents change, supports touch and Escape close controls, and closes on map reset.
- Use Inventory Item matches a validated JSON card by exact name and slot, decrements a valid stack count or removes its final use, changes no List when the card is missing, and routes to the required success or optional failure Event; its action definition survives map save/load and item changes use host-synchronized Player Lists in rooms.
- Show Variable Panel reads the selected scalar Map variable or triggering player's Player variable, refreshes when the value changes, supports touch and Escape close controls, and closes on map reset.
- Player Inventory installs fresh linked ids, stores one list per player, opens from I and an optional uniquely named touch Button, can collect a selected map object into that player's List, optionally saves the List and pickup state locally for solo play, and leaves existing mechanics untouched.

- Opt-in object-state saves reload for solo play on the same map and browser account; test runs and hosted rooms do not persist them.

- Player Respawns runs after checkpoint placement and plugin restoration, and guest-reported respawns do not trigger host-side mechanic replay.

Solid surfaces trigger only when the projected feet sweep reaches them from above; the player is aligned to the contact plane before rebound, overlap correction cannot erase the bounce, and hits from below remain ineligible.
