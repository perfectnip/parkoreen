🧰 Plugin Development

A practical path for creating and reviewing a Parkoreen plugin with the current API.

Current support: Plugin development and localhost preview are available to contributors. Plugins run as trusted scripts in the game page; importing a map or a .parkplugin archive does not install them. Public user installation and publishing are not supported yet.

Quick start

  1. From the repository root, create a starter folder: node tools/create-plugin.mjs my-plugin. Use a unique lowercase id with letters, numbers, and hyphens.
  2. Implement the behavior in the generated files under assets/plugins/my-plugin/. Declare scripts, sounds, assets, settings, controls, and dependencies in plugin.json; do not load code from map data.
  3. Run node tools/serve-plugin-dev.mjs. Open the printed local preview URL with the one-time token and your plugin id, for example ?pluginDev=my-plugin&pluginDevToken=TOKEN. The preview reloads when the selected plugin files change and does not add the plugin to the shared registry.
  4. Validate the folder: node tools/validate-plugin.mjs assets/plugins/my-plugin. Fix manifest, declared-file, path, control, dependency, and JavaScript syntax errors, then review the source and test it on a development map.
  5. For code review or transfer, create an archive with node tools/package-plugin.mjs assets/plugins/my-plugin and inspect one with node tools/verify-plugin-package.mjs my-plugin-0.1.0.parkplugin. Archives are not installable by Parkoreen.

Publishing boundary

The current API v1 is for trusted, bundled plugins. It does not provide enforceable permissions or a sandbox, so only run code you have reviewed. Local preview can load an unregistered plugin for development, but it does not install or publish it to players.

To include a reviewed plugin in Parkoreen, a maintainer adds its id to assets/plugins/manifest.json, checks its dependencies and declared assets, tests its behavior, and documents its settings and controls in the Plugins reference. The draft API v2 describes a possible isolated community-plugin path; it must be implemented and reviewed before player installation can be offered.

Need only gameplay rules?

Use the visual Mechanics editor when triggers, Events, variables, timers, and built-in actions can express the behavior. Plugins are for reusable code behavior that needs a supported plugin hook or API access.
