🔌 Plugins

An extensible plugin framework that adds optional mechanics on top of the base game.

Overview

Plugins are opt-in extensions enabled per-map in the Map Config panel. Multiple plugins can be active simultaneously. The bundled plugins are HK, HP, Controllable Jump, and Code (built into the mechanics runtime).

HK (Hollow Knight) plugin

Adds Hollow Knight‑style mechanics to the player character.

FeatureDescription
Mantis ClawPlayer can cling to and jump off walls.
Monarch WingsEnable a double jump and choose the number of extra jumps. Tune the upward force from 0.5× to 2× the map's normal jump force (default 0.85×).
AttackPlayer can slash in a directional arc. Choose Base or Quick Slash speed in Map Config; camera follow smoothness is set in the general camera settings.
PogoAttacking downward onto an enabled solid block or tilemap cell, spike, or Soul Statue bounces the player upward. Solid-surface pogo requires the projected feet sweep to reach the surface from above and places the feet on that contact plane before rebound; the long nail hitbox alone cannot trigger an early bounce while the player is still airborne above it.
Pogo strengthMap Config sets the bounce to 0.5–2× normal jump strength; the default is 1.2×.
Soul StatueNail hits restore soul energy and support downward pogo attacks, whether placed as a map object or as an obstacle acting type.
Visual effectsMap settings can turn nail slashes, nail-hit sparks, lateral shards and an upward rebound flare from down-slash pogo impacts, directional damage flashes after HP loss, landing dust, Soul Statue motes, camera shake, dash trails, and charge/Focus auras on or off, tune hit and landing shake, and choose effect colors. Completing a Focus heal releases a short pulse with radial motes in the configured heal color.

Combat tuning and effect controls are in Map Config → Hollow Knight. Impact effects also include a directional hit flash after the HP plugin confirms health loss; prevented hits do not flash. The impact setting controls a brief dust plume on landing and rising motes when a Soul Statue restores Soul. Camera shake can be disabled or tuned separately for hits and landings. If an older map has no saved effect settings, the effects remain enabled with the default colors and strengths.

HP (Health) plugin

Replaces instant-death hazards with a configurable health system.

FeatureDescription
Health Bar HUDOn-screen bar showing the player's current HP.
DamageHazards deal configurable HP damage rather than killing instantly.
HealSpecific objects (e.g. checkpoints with Heal at Checkpoints enabled) restore HP.

Code plugin (Mechanics editor)

Adds the Mechanics Editor — a visual block system plus Python scripting via Skulpt (an in-browser Python interpreter). Open it from the editor to build interactive logic without leaving the map.

Build a game mode from a template

  1. Open the Mechanics Editor and choose Templates. Templates add linked triggers, Events, and variables alongside existing mechanics; generated blocks stay editable.
  2. Choose Tag Game for a per-player Is It role. The host starts as “it”; when that player touches another player, the role transfers. Choose Hide And Seek for per-player hider/seeker/found roles, a shared hider count, and an Event that announces when no hiders remain.
  3. Switch to Flow map to follow the trigger → Event → branch links. Rename blocks and change messages, rules, or actions in their editors. Duplicate block names receive a suffix, and adding a template does not replace your existing mechanics.
  4. Save the map to keep the mode, then use Test Game for a local pass. For Tag and Hide And Seek, use a hosted room with multiple players to check role transfer and contact behavior; only the supported host-synchronized mechanics actions are shared authoritatively.

These templates are starter flows, not fixed game rules: extend them with timers, score or round variables, menus, checkpoints, object and tilemap triggers, and additional Events. For a new behavior, add one trigger or action at a time and inspect the Flow map to keep its links understandable.

Mechanic block types

BlockPurpose
TriggerDetects something happening in the world (game start, repeat timer, player input/action, room join/leave, zone enter/leave, object or tilemap contact, button press, player stats or health change, key combos). Each trigger can link to one event by id.
EventAn ordered list of actions that runs when a linked trigger fires. (Previously called "Action" — existing maps using codeData.actions and type: 'action' are auto-migrated to codeData.events / type: 'event' on load.)
VariableSingle values with string (up to 512 characters), integer, float, or boolean types. Map scope is shared for one map; Campaign scope shares state across maps that use the same Campaign Key and saves automatically in the current browser account (or device when signed out) during solo play; Player scope stores an independent value for each live player. Campaign saves do not sync to other devices and are not read or written in Test runs or hosted rooms. Enable Save this variable between visits for optional map- or player-scoped local saves. Lists can also be Map, Campaign, or Player scoped; each holds up to 100 typed string, number, or boolean items and can be changed by Event actions. Campaign Lists use the same stable key and local save rules. Player Lists are useful for per-player inventories and collections. They are separate by player, not secret: hosted snapshots are sent to every client.

Switch the Mechanics Editor dashboard between Blocks and Flow map. The flow map shows trigger, event, and variable nodes, with lines for trigger links, event calls and branches, timers, and variable use. Trigger and Event cards also provide direct links to their connected Events and referenced Variables. Select a node or focus it and press Enter to edit that mechanic; on narrow screens, scroll horizontally to inspect the full map. The dashboard warns about nested Event paths that may exceed the runtime's depth or action-chain limits, along with event-link cycles that cross a Start Timer action. Intentional timer loops are allowed, and a map stops timer events after 10,000 fires. The Basic HK Enemy template links a selected object to nail-hit damage and an optional defeat Event. Its setup can also create a timed left-right patrol and an object-contact trigger that calls the HP damage hook. Patrol motion is shared from the room host, but nail-hit health changes and player contact damage remain client-local in hosted rooms.

Trigger types

TriggerDescription
Game StartsEach Game Starts trigger fires once when the game begins.
Game EndsFires locally once after the player reaches an endpoint and its completion requirements are met. Python context includes game_elapsed_ms and game_was_test_mode. Use it to show a local result or completion message; hosted rooms do not replay this guest-local event on the Worker.
Player Joins Room / Player Leaves RoomFires once when a guest joins or leaves while the host keeps a multiplayer room running. The host runs the linked event once and shares its map changes. A leave event runs after the guest is removed from the live roster and before their player-scoped values are cleaned up. These triggers do not fire for players who were already in the room when its map started; when the host leaves, the room ends.
RepeatFires first after the selected interval, then repeats on that cadence: ticks (about 60 per second), seconds, or minutes. Intervals range from 1 unit to 24 hours.
Player Action InputFires for supported movement actions such as jump, fall, move, teleport, and touching another player. It also lists the declared custom controls from enabled plugins and fires once when one is pressed (for example, the Hollow Knight plugin's Attack, Dash, Super Dash, and Focus controls). Custom-control events run locally in multiplayer; they do not request host-authoritative changes. Some built-in actions require a positive value (e.g. Fall for [time]). Older maps that omit it use defaults: 1 second for timed actions and 100 pixels for fall distance.
Player Key InputFires on a multi-key combination (alphabet / number / mouse / arrow / modifier / custom captured keys). Combinations support up to 16 distinct keys.
Player JumpsFires after a core or plugin jump actually succeeds. Event context includes jump_was_grounded and jump_source (core or plugin). In hosted rooms it runs locally on each client; guest jumps are not host-validated.
Player Enter Zone / Leave ZoneFires when the player crosses a named Zone.
Player LandsFires once when the player transitions from airborne to solid ground. Event context includes surface_object_id and surface_object_name for the landing surface. In hosted rooms it runs locally on each client; guest landings are not host-validated or replayed by the Worker.
Player Attacks ObjectRequires the Hollow Knight plugin. Select a map object; the trigger fires once per target object during each nail swing. The Event receives touched_object_id, touched_object_name, and attack_direction (up, down, or forward). Enable Down slash rebounds from this target for enemies or breakable objects that should be pogoable. This is a local trigger in hosted rooms and is not validated or replayed by the Worker.
Player Press ButtonFires when the player activates a Button.
Player Touches ObjectChoose a map object and detect first contact using a box, a circle centered on the object (radius is half its shorter side), or a capsule. The trigger rearms after the player leaves, so standing against an object does not fire it every frame. This setting controls trigger contact only; solid collision uses the object's separate collision shape.
Player Touches TilemapChoose a tilemap and detect entry into any collidable cell, optionally filtered to solid, one-way (including either ramp direction), or damage cells. Decorative cells are ignored. It fires once while the player remains in the selected tilemap and rearms after leaving. Custom convex tile polygons use their actual shape for this contact; one-way polygon cells match the one-way filter. Python event context includes the touched cell's stable id and tilemap name. Hosted rooms check the reported overlap against the saved tilemap and recent client position; movement is still client-reported.
Player StatsFires once when a player stat (account username, display name, host/guest, color, or tag) starts matching a value. It can fire again after the match stops and becomes true again. Host/Guest accepts only host or guest and is available only in a multiplayer room. Username checks the account username rather than the display name. Tag reads player.tag when a plugin or gameplay feature supplies one. Values are limited to 128 characters.
Player Health ChangedRequires an enabled health plugin that supplies numeric player.hp (the bundled HP plugin does). It fires when health changes, or only when it increases/decreases. Its first reading seeds a per-player baseline without firing; Mechanics records a runtime error if no numeric health value is available. Events receive player_hp, player_max_hp, health_before, health_after, and health_delta through parkoreen.get_context(). Guest health is not host-validated in multiplayer; the Worker rejects guest requests using this trigger.
Player DiesFires locally once at the actual death transition, before automatic respawn. Event context includes death_source_id, death_source_name, and death_source_type for hazards, void falls, and Mechanics damage. It is client-local in hosted rooms.
Player RespawnsFires locally after the player has been moved to their checkpoint or spawn and the other respawn hooks have restored player state. Use it to reset round variables, show a message, or start post-respawn mechanics. In hosted rooms it runs on each player's client and does not ask the host to replay a guest-reported respawn.
Variable ConditionFires when a map variable first matches globally or when a player variable first matches for the triggering player (equals, does not equal, greater/less than, true/non-empty, or false/empty).

Event actions

Link an Event in a trigger's Run Event field. Its actions execute from top to bottom; use the ↑ and ↓ controls in the Event editor to reorder actions while preserving their current field values. Use Branch on Variable to compare a map variable, the triggering player's variable, or (in a Touch Other Player event) the touched player's variable, then route to a true event or an optional false event. A Run Event action can call a reusable event inline; the editor warns about recursive links, disabled event targets, and enabled events with no route from a trigger. Each event holds at most 128 actions, and each triggered chain is limited to 256 actions and 16 nested events.

ActionBehavior
Set / Add / Toggle VariableChange a map-shared, campaign-shared, or player-scoped string, number, or boolean value. Player variables can target the triggering player, the player touched by a Touch Other Player event, or all live players. Add accepts integer and float variables; Toggle accepts booleans. Campaign values save locally across maps during solo play.
Branch on VariableCompare a single-value Map or Campaign shared variable, or a Player variable (optionally checking the touched player in a Touch Other Player event), then run the selected true or false event. A touched-player condition has no match when the event has no touched player.
Branch on Player CountCount connected players whose per-player variable matches a condition, then branch on whether that count equals, exceeds, or is below a number from 0 to 100. In a hosted room, the host evaluates the branch against the live room roster and publishes any shared state changed by its branch.
Branch on Object HealthCompare a selected object or the object touched by this Event against a whole-number health value, then run the true or optional false Event. Set Object Health or Damage Object must initialize that object's temporary health first. Supported hosted trigger flows evaluate this branch from synchronized health state; local-only triggers remain local.
Set / Damage Object HealthSet or subtract temporary per-object health for a selected or touched object. Objects with active temporary health show a compact health bar above them during play; defeated objects hide it. Damage can disable the object at zero and run an optional defeat Event. Event Python receives health_object_id, health_object_name, object_health, object_max_health, and object_defeated. Health resets with the play session; the room host synchronizes it for supported shared trigger flows. HK nail-hit triggers remain client-local because the Worker does not validate attack geometry.
Add / Remove / Clear / Branch on List ItemAdd or remove the first matching typed item in a Map or Campaign List, or target a triggering/touched player's separate List (mutations can target all live players). Clear List empties the selected List. Branch on whether a typed item is present. Items use strict type and value matching; each List holds at most 100 items. Map and Player Lists can opt into browser-local saves for solo play; Campaign Lists save automatically across maps during solo play. Test runs and hosted rooms neither load nor write local List saves; hosted rooms sync shared and player List values from the host to every client. Player scope separates state; it does not hide it from other clients.
Set Inventory Item EquippedFind a named JSON inventory card in a Player-scoped string List, set its equipped state, and enforce one equipped item per slot for that target player. Other cards in a different slot remain equipped. Hosted Events synchronize the resulting Player List from the host.
Branch on Equipped ItemCheck whether a named card is equipped in a selected slot for the triggering or touched player, then run the matching true or false Event. Branch links appear in the Flow map and are checked for recursion.
Use Inventory ItemConsume one matching card for the triggering or touched player. A stack count above 1 is decremented; a card without a count or with a count of 1 is removed. The required success Event can apply the item effect, while an optional failure Event handles a missing item. Hosted Events synchronize the Player List through the room host.
Set Object EnabledActivate or deactivate a map object during play or a test run. Disabled objects stop rendering, collision, damage, and interactions. By default the state resets when the session ends; select Remember this object state between visits to save it locally for solo play on this browser. Test runs and hosted rooms remain temporary.
Set Trigger EnabledEnable or disable a selected trigger for the current play session. This lets events gate later puzzle, round, or one-shot interactions. Runtime state resets to the saved map setting when play restarts; in hosted rooms the host publishes the validated trigger state, and the Worker rejects requests for triggers the host disabled.
Spawn / Remove Spawned ObjectsSpawn a temporary copy of an authored object next to the triggering player, grouped by a 1–64 character tag, or remove every live copy with that tag. Set an instance cap per tag and an optional lifetime from 0 to 3,600 seconds (0 means until removed or the session ends); the map has a hard cap of 64 copies. Copies keep the template's size, appearance, and collision, can activate a Player Touches Object trigger configured for their template, and reset when play or a test ends. Zones, buttons, portals, checkpoints, spawn points, and endpoints cannot be templates. Hosted rooms receive the host's validated template id, position, and tag for each copy.
Set Object PositionMove a selected map object immediately to finite map-space X/Y coordinates. Collision and spatial caches update with the new position. Hosted rooms receive the host's validated position snapshot.
Move Object (Animated)Move any selected map object to X/Y coordinates over 0.01–60 seconds with Linear, Ease In, Ease Out, or Ease In and Out timing. A new move replaces the current move; Set Object Position cancels it. Solid ground carries a player standing on top. Motion returns to the authored location when play ends. Hosted rooms synchronize the host's validated movement path.
Set Camera Follow AxesSwitch this client's camera between both axes, horizontal-only, and vertical-only tracking for the current session. The authored Map Config value returns on restart. This changes presentation locally; it does not synchronize camera state to other players.
Set Camera BoundsUse the Map Config rectangle, remove bounds for this session, or apply a custom rectangle to this client's camera. Custom bounds are limited to a positive rectangle inside ±10,000,000 map pixels. The saved map setting returns on restart; camera bounds are local presentation and do not synchronize to other players.
Set GravityUse the saved Map Config gravity or set gravity from 0 to 5 for the current session. Core and Hollow Knight movement use the same override, hosted rooms synchronize the validated value from the host, and restart restores the map value.
Set Jump ForceUse the saved Map Config jump force or set an upward force from -100 to -0.1 for the current session. Core jumps and Hollow Knight jumps, wall jumps, and pogo use the same override; hosted rooms synchronize it from the host, and restart restores the map value.
Set Player SpeedUse the saved Map Config movement speed or set a horizontal speed from 0.1 to 100 pixels per tick for the current session. Core movement and Hollow Knight wall movement use the override; hosted rooms synchronize it from the host, and restart restores the map value.
Set Movement ControlTemporarily set horizontal acceleration (0–20), air control (0–1), or terminal fall speed (1–100 px/tick), or restore that Map Config value. Core movement and Hollow Knight wall movement share the effective settings; hosted rooms synchronize values from the host, and reset restores Map Config.
Set Object Sprite FrameHold an object with a sprite sheet on a selected frame for a visual state, or resume its automatic animation. Target a selected map object or the touched object that spawned the Event; for spawned objects, choose the source template's sprite sheet. The selected frame is shared from the room host and resets when the session ends.
Play Object Sprite AnimationPlay a row-major range or a named clip from a sprite sheet at 1–30 FPS, either looping or holding the last frame, or resume automatic animation. Target a selected map object or the touched object that spawned the Event; spawned instances use their selected source template's clips. A one-shot animation can run an optional completion Event; the host runs it once in a hosted room. The frame range is validated against the sheet, start time and settings sync from the host, and reset restores the authored loop.
Set Object OpacityTemporarily fade any map object from fully transparent (0) to opaque (1), or restore its Map Config opacity. Collision stays independent from appearance; the host synchronizes the override and play reset restores the authored value.
Set Tilemap Cell BehaviorChange an existing 32×32 cell on a selected tilemap to solid, one-way, either ramp direction, damage, or decorative. Target a fixed grid coordinate or the cell touched by the triggering Player Touches Tilemap event. The change is temporary and resets with the play session; hosted rooms sync validated cell behavior from the host.
Set Player CheckpointSets the triggering local player's respawn target to an enabled Checkpoint object and fires the player.checkpoint plugin hook. This can be triggered by a zone or other mechanic instead of physical contact with the checkpoint. Turn on Remember the player's latest checkpoint in Map Config to resume there on later visits.
Start / Stop TimerStart a named timer that runs an event after a delay, optionally for a fixed number of repeats, or stop that timer. The callback retains the player who started it so delayed player-scoped actions still target that player in hosted rooms. Sound and message actions are local presentation and are not part of host-synced state. Timers reset on map load, game start or end, and when playtesting stops. A map supports 128 active timers, delays up to 24 hours, at most 1,000 repeats per timer, and 10,000 timer fires per session. The dashboard marks cycles that can keep rescheduling timer events.
Teleport Player / Teleport Player Above ObjectMove the triggering player to map coordinates (each limited to ±10,000,000 pixels) or place them centered above an enabled map object such as a checkpoint, spawn point, or platform. Both teleport actions clear velocity and rearm jump; coordinate teleports remain supported for existing maps. Set Player Velocity sets horizontal and vertical speed components, each limited to ±10,000 map pixels per update.
Damage PlayerRuns the player's damage hook so the HP plugin can apply its configured behavior. Without a plugin handling damage, the player dies.
Heal PlayerRestores the selected amount of HP, up to maximum HP. Requires the HP plugin.
Transition to MapLoads a saved map by id, places the player at its saved checkpoint (solo Play only), spawn point, or default start, resets scene-local Mechanics state, and fires the destination map's Game Starts triggers. Browser-local saves are scoped to the destination map while it is active. From Game Ends, it resumes the run in the next scene; if loading fails, the normal completion screen appears. This ends the current event chain; place it last and move follow-up logic to the destination's Game Starts event. Works in solo Play and Test, but not multiplayer rooms.
Restart SceneRestarts the active scene, resets scene-local Mechanics state, and fires Game Starts again. Solo Play uses the remembered checkpoint when enabled; Test always starts at the Spawn Point or default start. It ends the current Event chain and supports solo Play and Test, including an unsaved editor map; multiplayer restarts are unavailable.
Play SoundPlays one of the built-in gameplay sounds on the local client.
Play Plugin SoundPlays a sound declared by an enabled plugin, with volume from 0 to 1. It follows the Event's execution side and is not broadcast; in a hosted room, the host hears it when the host runs a shared Event, while local Events play on the client that triggered them.
Stop Plugin SoundStops the selected enabled plugin sound on the client running the Event. It also stops every audio variant in a randomized sound group, which lets an Event end looping audio during a scene change, dash, or round transition.
Run EventRuns another event at this point in the action sequence, so common behavior can be reused.
Show MessageShows a timed message on the local client.
Show List PanelOpens a local, scrollable panel for a Map, Campaign, or Player List and refreshes its contents while play continues. Close it with the on-screen button or Escape. A Player List displays the triggering player's values. Bind this action to a key or button trigger to make an inventory or collection easy to open. Hosted Player List data is visible to every client.
Show Variable PanelOpens a local live status panel for a string, number, or boolean Map, Campaign, or Player variable. Map and Campaign variables show shared state; Campaign values save across maps in solo play. Player variables show the triggering local player's own value. The panel refreshes during play, closes with its button or Escape, and does not pause gameplay.
Show DialogueOpens a speaker panel with up to 12 pages (one non-empty line per page, 512 characters each). Enter, Space, or the touch-friendly button advances. The local player pauses until the final page closes. Dialogue yields the event chain; place it last, and the editor checks linked events that can yield too. Legacy Python for the event runs after dismissal.
Show ChoicesOpens a speaker prompt with 2–8 labeled options. The option list scrolls within a bounded height on small screens. Each option runs its linked enabled event, then resumes the parent event’s legacy Python. The prompt and selection are local to that player. For supported hosted trigger flows, the host first replays the trigger-linked declarative Event in order and records the enabled options it reaches; the Worker and host then validate a selected route before the host runs its shared actions. Other actions remain local. The editor rejects duplicate labels and recursive event chains, and the Flow map shows each option link.
Show MenuOpens a centered, titled menu with 1–8 linked options. Escape or clicking outside closes it; optionally route either action through a cancel Event. The local player pauses and the option list scrolls on small screens. An optional setting also pauses solo scene simulation and Mechanics timers; in hosted rooms, only the local player pauses. Selected Events run before the parent Event’s Python resumes. Variable conditions can react to changed values, and event branches can route later actions from map, campaign, or player state. Together with object activation, positioning, movement, and temporary spawned copies, they support switches, doors, hazards, moving platforms, projectiles, collectible drops, counters, checkpoints, and round-state flows. Spawn templates stay authored in the map; runtime copies are temporary and capped at 64. Persistent scalar variables, Campaign state, opted-in object states, and the optional latest-checkpoint save are stored locally in the browser under the signed-in account, or under a browser-device id when signed out. Test runs do not write progress, saves do not sync between devices, and object-state persistence applies to solo play. In hosted rooms, the host publishes shared and per-player variables, object-enabled states, changed object positions, bounded movement paths, and temporary spawned copies; the Worker checks ids, template eligibility, tags, value types, coordinates, live player session ids, payload size, revisions, and host ownership before relaying them. For supported guest trigger flows, the host replays the linked declarative Event in order, evaluates its branches, skips local-only presentation and legacy Python, and records enabled choice routes when it reaches Show Choices or Show Menu. The Worker checks that a selected route belongs to the saved parent Event, then the host accepts only a route in its pending record before running that Event's shared actions. Player effects and presentation stay local.

For an inventory view, create a Player-scoped string List, add or remove items through Events, then link a Player Key Input trigger to an Event with Show List Panel set to that List. The panel refreshes as the List changes and closes with its button or Escape. Existing typed values still display as text. For a richer card, store a JSON object in a string item, for example {"name":"Key","icon":"🗝️","description":"Opens the east gate","count":2,"slot":"key","equipped":false}. The required name is up to 80 characters; the optional text icon is up to 8, description is up to 180, count is an integer from 1 to 9999, slot is up to 32 characters (defaults to default), and equipped is a boolean. The full JSON string must fit within the normal 512-character List string limit. Text is rendered as text, not HTML. Use Set Inventory Item Equipped to equip or unequip a named card for the triggering, touched, or all live players; equipping a card unequips other cards in the same slot. Use Branch on Equipped Item to run separate Events depending on whether that named item is equipped for the triggering or touched player; these branch links are checked for recursion and shown in the Flow map. Use Use Inventory Item to consume one matching card and route to a success Event that applies its effect or an optional failure Event if it is missing. Hosted Events synchronize these values through the room host.

To show a score or round status, create a scalar Map, Campaign, or Player variable, update it in Events, then use Show Variable Panel with a key or Button trigger. Map variables show map-shared state; Campaign variables show cross-map solo progress; Player variables show the triggering player's value. The local panel refreshes as the value changes and does not pause gameplay.

For guest requests that can change shared room state, the Worker rechecks zone entry/leave transitions, map-object contacts, named Button contacts, tilemap-cell contacts, key combinations, Map/Player Variable conditions, and Touch Other Player contacts against the saved map, host-published variable state, and recent client-reported positions. It derives the touched object or player id and latches contact triggers until the player leaves, so repeated requests cannot replay one contact continuously. The client still supplies the positions and key samples; the Worker does not simulate movement or physics, and a modified client can falsify those samples. Other local triggers—including plugin controls, health changes, jumps, landings, deaths, and respawns—are not replayed by the Worker. Legacy Python event code is never run during a guest-request replay. Cheat-resistant tag or hide-and-seek rules still need authoritative movement, physics, and validation of every gameplay action.

Mechanics templates

The Title Menu template runs from Game Starts, shows a Welcome screen with a touch-friendly Start option, and pauses solo scene simulation until the player starts. The editor prevents adding another Game Starts menu so startup does not queue multiple overlays.

The Pause Menu template adds a keyboard Escape trigger and a Resume/Restart menu that pauses the solo scene simulation and Mechanics timers. Select an existing Button object during setup to also open it with a tap-friendly in-game button on phones and tablets. The editor prevents adding a second Escape-triggered menu so a single key press cannot queue duplicate overlays; edit the generated Event to customize the options.

The Basic HK Enemy setup binds an existing map object to the Hollow Knight nail-hit trigger, temporary health, and a defeat Event. Set a patrol distance above zero to generate two timed Move Object Events that alternate between endpoints; set it to zero to leave the object stationary. Sprite-sheet artwork automatically faces the direction of horizontal travel. Set contact damage above zero to add a Player Touches Object trigger and Damage Player Event. Defeat stops the patrol timer. Hollow Knight must be enabled for nail hits, and its HP dependency handles contact damage; in hosted rooms patrol motion is host-synchronized while nail-hit health and contact damage remain client-local.

Choose Templates in the Mechanics Editor to add an editable starter flow. The Player Inventory template creates an empty Player List, an I-key trigger, and a live inventory panel; you can also bind an existing uniquely named Button object for touch activation. Optionally select a pickup object to add its display name to the triggering player's List and disable the map object when collected. Its setup can opt into saving the list and pickup state locally between visits for solo play in that browser. Test runs and hosted rooms stay temporary, and saves do not sync between devices. Add or remove items through Events and edit the generated blocks as needed. The Timed Round template starts a 60-second timer when play begins, sets a map-scoped round state, and shows start/end messages. The Timed Course template asks you to select two existing named zones, starts a shared 120-second deadline when a player enters the start zone, and completes when a player reaches the finish zone. The Button Switch And Door template binds a uniquely named button to a map object, resets that object to enabled at game start, and toggles it on each press. The Checkpoint Zone template binds a zone to an existing Checkpoint object; entering the zone sets the local player's respawn target and runs the normal checkpoint hook. The Button Save Point template binds a uniquely named Button to a Checkpoint object; pressing it sets the player's respawn point. Enable Remember Latest Checkpoint in Map Config to resume there on a later solo visit in the same browser. The Tag Game template starts with all players untagged, makes the host “it,” and passes the role when the current tagger touches another player. The Hide And Seek template starts with the host as seeker, changes touched hiders to a found role, updates a shared found counter, and completes the round when no connected hiders remain. Templates are additive and use fresh block ids, so they can be installed more than once without replacing existing mechanics. The dashboard shows clickable flow links from triggers to their events and between events; invalid links, recursive event chains, and unreachable events are flagged before play. Adjust template event values and timer duration for your map. Hosted zone and contact checks use recent client-reported positions, so multiplayer templates are suitable for trusted playtesting but not cheat-resistant rounds.

Python event API v1

Python attached to an Event can import parkoreen. The API is available only while that event runs; standalone compiler runs have no event context. parkoreen.API_VERSION is 1. get_context() returns a read-only snapshot with api_version, event and trigger ids/names/types, player id/name/username, position, size, velocity, grounded/dead flags and remaining jumps, source, target, and touched player ids, plus touched object id/name, attack direction, landing surface id/name, jump origin/source, death source, game completion time/test status, and health change values when applicable. Game Ends fields are game_elapsed_ms and game_was_test_mode. Player Dies fields are death_source_id, death_source_name, and death_source_type. Jump fields are jump_was_grounded and jump_source. Player Attacks Object also supplies attack_direction. Health fields are player_hp, player_max_hp, player_health_percent, health_before, health_after, and health_delta. With the Hollow Knight plugin enabled, context also includes player_soul, player_max_soul, player_is_attacking, player_attack_direction, player_is_dashing, player_is_super_dashing, player_is_super_dash_charging, player_is_wall_clinging, player_is_healing, player_has_dash, player_has_super_dash, player_has_mantis_claw, player_has_monarch_wing, and player_monarch_wings_used; these fields are None when the plugin has not initialized the value. Position and velocity fields are None when unavailable; grounded, dead, and jumps fields are also None when the runtime does not provide them. The interpreter cooperatively yields about every 8 ms and stops a script after 100 ms; input() is disabled so a game event cannot leave a blocking prompt open.

player_health_percent reports player_hp as a percentage of a positive player_max_hp, or None if either value is unavailable or the current HP exceeds the maximum.

import parkoreen

context = parkoreen.get_context()
print("event:", context["event_name"])

if parkoreen.set_variable("round_state", "started"):
    parkoreen.append_list_item("round_log", "started")
    parkoreen.show_message("Round started", 3)
context = parkoreen.get_context()
soul = context["player_soul"]
if soul is not None and soul >= 33 and context["player_has_mantis_claw"]:
    parkoreen.show_message("Soul is ready; Mantis Claw is available", 2)

get_players(offset=0, limit=32) returns a page of at most 64 players currently visible to this client, including the local player when available. Each read-only snapshot contains id, display name, position, size, velocity, and grounded/dead flags; it does not expose account usernames. Invalid ranges return None. Hosted snapshots reflect the latest client-side remote-player state and are for presentation or local event logic, not authoritative game rules.

get_variable(key, scope=None) and set_variable(key, value, scope=None) accept a variable id or a unique exact name. The optional scope is "map", "campaign", or "player"; it must match the variable. Only enabled single-value string, integer, float, and boolean variables are exposed. Reads return None for an unknown or ambiguous variable; writes return False for an invalid key, scope, or value. Campaign values use the same stable Campaign Key and local solo-save behavior as declarative Event actions. Player-scoped values refer to the event's player.

get_player_variable(key, player_id) and set_player_variable(key, value, player_id) access an enabled Player variable for a currently visible player. Use an id from get_players(); in solo play, the local player id is "local" if no id is assigned. They return None or False for unknown players, invalid values, or non-Player variables. In a hosted room only the host may write, and accepted values are published through the synchronized Mechanics state. Guest scripts cannot write shared Player variables.

get_objects(offset=0, limit=100) returns a page of at most 128 read-only object snapshots, and get_object(object_id) reads one snapshot by id. Each snapshot includes id, name, position, size, type, enabled state, collision shape, normalized polygon points and polygon one-way mode where applicable, one-way-platform state, whether the object is a temporary spawned copy, and active object health (object_health, object_max_health, and object_defeated; these are None until health is initialized). The TypeScript starter defines box, circle, capsule, slopeUpRight, slopeUpLeft, and polygon shapes; capsule colliders round both ends along the block’s longer axis and are solid on every side. getSlopeSurfaceY(object, x) reads the top surface height for a ramp or polygon and returns null outside the shape. Use ids from snapshots or event context. get_object_health(object_id) returns a health dictionary (current, maximum, defeated) or None when the object has no active health. set_object_health(object_id, current, maximum) accepts whole numbers from 0 to 99,999, requires current health not to exceed maximum, and reuses the Mechanics action so a zero-health object is disabled. Both use temporary session state; in hosted rooms only the host can write and accepted health is synchronized. set_object_enabled(object_id, enabled) and set_object_position(object_id, x, y) also reuse the Mechanics Editor's validated actions; positions are limited to ±10,000,000 pixels. Invalid values return False, and guests cannot write shared map state. Python object changes are temporary; use a declarative Set Object Enabled action with persistence enabled to save an object's state between solo visits.

get_tilemaps(offset=0, limit=64) returns bounded summaries of native tilemaps, including each id, name, draw layer, cell count, and atlas frame dimensions without copying the atlas image. get_tilemap_cells(tilemap_id, offset=0, limit=100) returns a page of at most 128 cells with stable ids, grid coordinates, collision behavior and shape, polygon points when present, color, texture, opacity, atlas frame, and animation settings. The map supports up to 64 tilemaps and 100,000 cells; invalid ids, invalid ranges, or offsets above the 100,000-cell cap return None, while a valid page past the end is empty. set_tilemap_cell_behavior(tilemap_id, x, y, behavior) changes an existing grid-aligned cell to solid, oneWay, either ramp, hazard, or decorative, then returns whether it changed. Changes follow Mechanics reset behavior; guests cannot write these shared cells in hosted rooms, and a room host publishes accepted changes.

set_player_velocity(vx, vy) changes the event player's horizontal and vertical speeds when both values are finite and within the Mechanics limit of ±10,000 pixels per update. It returns False when the player or values are unavailable. In hosted rooms this controls the local player's movement only; use declarative Mechanics actions for host-published shared map changes.

get_list(key) returns a copy of an enabled Map or Campaign List, or the event player's Player List, as dictionaries with value_type and value fields; it returns None for an unknown or ambiguous List. list_contains(key, value, value_type=None) checks a typed item and returns None when the key or type is invalid. append_list_item(key, value, value_type=None) and remove_list_item(key, value, value_type=None) mutate bounded typed Lists; clear_list(key) empties an enabled Map, Campaign, or event-player List. These functions return whether the operation changed the List. Item types are string, integer, float, and boolean; integer values must be safely representable whole numbers, and pass value_type when an integer-valued number should be treated as a float. Each List is limited to 100 items. Guests cannot write shared Lists in hosted rooms; the host publishes successful changes. Campaign Lists save locally across maps in solo play; regular local List saves follow the map's opt-in setting. Neither save type is read or written during test runs or hosted play. show_message(text, duration_seconds=3) displays a local message.

get_player_list(key, player_id), player_list_contains(key, player_id, value, value_type=None), append_player_list_item(key, player_id, value, value_type=None), remove_player_list_item(key, player_id, value, value_type=None), and clear_player_list(key, player_id) operate on a live player's enabled Player List. Use an id from get_players(); the same 100-item bound and typed values apply. Read methods return None for unknown players or Lists; writes return whether they changed the List. Only the host writes Player Lists in hosted rooms, and successful changes use the synchronized Mechanics state. Persistent Player Lists remain local-only and are not used for other players.

In hosted rooms, Python event code runs locally and is skipped during the host's authoritative replay of a guest event request. Guest Python scripts cannot write mechanics variables or shared object state; the host can publish accepted writes. Python scripts are not a server-verified gameplay surface, so use declarative actions for shared rules that need host validation.

The Mechanics Editor and its scripting surface are beta. Hosted rooms forward only supported guest triggers. The Worker checks zone, object, button, tilemap, and player-contact overlap against recent client-reported positions; it checks Map and Player Variable conditions against host-synced state and key combinations against guest-reported pressed keys. Position and keyboard samples are still supplied by the client, and the Worker does not simulate authoritative physics or input. Treat multiplayer mechanics as trusted playtesting, not cheat-resistant rules. Existing maps migrate the old actions field to events; keep a copy of a map before experimenting with scripts.

Developing a plugin

For a local preview without editing the shared plugin registry, run node tools/serve-plugin-dev.mjs from the repository root. Copy the per-server token printed in the terminal, then open http://127.0.0.1:4173/parkoreen/host.html?pluginDev=example&pluginDevToken=TOKEN, replacing example with your plugin folder id and TOKEN with that value. To preview up to eight related plugins together, use comma-separated ids such as ?pluginDev=example,example-helper&pluginDevToken=TOKEN; this lets local plugins resolve dependencies without registering them. The token prevents an unrelated web page from silently initiating a preview and is required to fetch unregistered plugin files and connect the reload stream. The plugins appear in the editor library with their manifest-defined settings; supported boolean, number, select, and string fields are editable and showIf dependencies control visibility. The page reloads when files in any selected plugin folder change; save map edits before changing plugin source. This mode works only on localhost, fetches fresh plugin files, and does not add plugins to assets/plugins/manifest.json. Plugins still execute as trusted page code with access to the page, so use only code you wrote or reviewed. The token is a local preview guard, not a sandbox or a player install path.

The starter's plugin.json links to the manifest schema for JSON completion and validation. It also includes API v1 TypeScript declarations. Its inject.js uses JSDoc to attach those types to the plugin context, so editors such as VS Code can offer completions and inline type information for the documented hooks and API methods while authors work in JavaScript. The declaration file is development aid only; it is not loaded by the game.

API v1 also exposes the player.attack.hit hook when the Hollow Knight plugin is enabled. It supplies the attacking player, world, hit map object, slash direction, and a pogoable flag. Set data.pogoable = true and return the payload to make a down-slash hit on that object rebound the player; use this for local reactions or custom combat. Mechanics sets the same flag when an enabled Player Attacks Object trigger marks its target as pogoable. This hook and its rebound behavior are local in hosted rooms.

Plugin types expose each ground object's collisionShape and the optional player.collisionShapeIntersectsBox(bounds, object) overlap helper. Use player.getCircleVerticalContact(object, bounds, direction) for circle surfaces and player.getCapsuleVerticalContact(object, bounds, direction) or player.getCapsuleHorizontalContact(object, bounds, direction) for capsule surfaces; direction is 1 for the top or right surface and -1 for the bottom or left. A plugin that handles custom movement can use these helpers to respect box, circle, capsule, ramp, and polygon colliders.

Parkoreen's bundled plugins are packaged under assets/plugins/<id>/ and listed in assets/plugins/manifest.json. A plugin manifest describes its name, version, dependencies, config fields, scripts, sounds, named general assets, controls, and optional editor features. Declare sprite sheets, images, JSON, and other plugin files under assets; resolve a declared name with ctx.api.getAssetUrl(name), which returns a versioned URL or null for an undeclared name. Generate a starter with node tools/create-plugin.mjs example from the repository root, replacing example with your lowercase plugin id. The starter declares an SVG marker asset, loads it with getAssetUrl(), and draws it above the player with the render.player hook; using the localhost development preview above, you can change the example and see it in a map without editing the shared plugin registry. Read the API v1 plugin template and its render-hook source. Follow the manifest schema and run node tools/validate-plugin.mjs assets/plugins/example before submitting a bundled plugin. The validator checks config defaults and boolean showIf references, controls, editor feature flags, object guards, declared file paths, and declared .js syntax without running the code. Preflight rejects individual files over 64 MiB, combined manifest and assets over 128 MiB, and packages exceeding the 256-entry limit before parsing JavaScript. It checks dependency chains against bundled plugins and sibling plugin folders, rejects known cycles, and warns when a dependency is unavailable for local preview. The editor lists map plugin ids missing from the reviewed library and reports registered plugins that fail to initialize; saved plugin settings remain preserved. Importing a map never installs or executes plugin code. Run node tools/package-plugin.mjs assets/plugins/example to create an example-0.1.0.parkplugin review/transfer archive in the repository root, or pass an output path and --force to replace an existing file. Verify a received archive with node tools/verify-plugin-package.mjs example-0.1.0.parkplugin; it checks ZIP structure, safe paths, declared-file membership, sizes, CRCs, and SHA-256 hashes without extracting or executing code. The archive contains only the manifest and its declared runtime assets, records their SHA-256 hashes and sizes in plugin-package.json under the package metadata schema, and is limited to 64 MiB per file and 128 MiB total. Hashes can detect accidental changes but do not identify the publisher. It is not installable by Parkoreen and does not sandbox or certify the plugin.

  1. Generate assets/plugins/<id>/ with the scaffolder or create it manually. Use a unique lowercase id, a plugin version, and the supported apiVersion. Preview an unregistered plugin through the localhost development mode above.
  2. Put the declared source files and media under that plugin folder. Keep asset paths relative and do not use parent-directory paths.
  3. Run the plugin validator, review every source file, and create a .parkplugin transfer archive if needed. The archive is a convenience for code review, not an installable package.
  4. Add the id to the plugins array in assets/plugins/manifest.json only after maintainer review. Declare dependencies explicitly, test it on a development map, and document its controls, configuration, and compatibility in this Guide.

  "name": "Example",
  "version": "0.1.0",
  "apiVersion": 1,
  "description": "A small gameplay extension",
  "author": "Your name",

The inject script receives an API v1 context with ctx.api and legacy trusted fields ctx.pluginManager, ctx.pluginId, ctx.world, ctx.hooks, and ctx.sounds. Use ctx.api.registerHook(name, callback, priority) to add a hook with automatic cleanup, ctx.api.addEventListener(target, event, callback, options) for a tracked browser listener, ctx.api.onCleanup(callback) for timers/resources, ctx.api.getConfig() for a copy of plugin config, and ctx.api.playSound(name, volume) for this plugin's declared sounds. Keep plugin state under a plugin-specific namespace and register timers/listeners through cleanup helpers so disable and map changes release them. The validator parses declared JavaScript syntax but does not review behavior; API helpers manage lifecycle but do not restrict trusted scripts or sandbox them. API v1 rejects a permissions field because it cannot enforce one.

The plugin starter demonstrates a declared three-frame sprite sheet loaded with getAssetUrl, frame selection in render.player, and a static-image fallback. Use it as a small example when building animated plugin visuals; larger spritesheets should remain declared plugin assets rather than being copied into a map's mechanics data.

Plugin API versions and migration

The manifest's version is the release version of your plugin; apiVersion is the runtime contract. The current runtime supports API v1 only. For compatible behavior, configuration, or asset updates, bump the plugin version and keep apiVersion at 1; the runtime includes that release version in declared script and sound URLs to refresh cached assets. Do not change a v1 hook payload, API method, or manifest field's meaning without a new supported API version. Do not set a future API version until the runtime explicitly supports it. Permission requests are not supported in v1 and are rejected by both preflight and runtime discovery. The separate API v2 protocol draft, message schema, and TypeScript declarations describe a future isolated message API with separate map and player snapshot grants; these artifacts are not implemented or installable.

The API v2 draft now also specifies paged, read-only native tilemap cell snapshots under the proposed map.read grant. Pages include collision behavior, shape, and normalized polygon geometry so a future isolated plugin can reason about the 2D map without receiving live engine objects. This is a draft contract only; the current runtime does not provide this method.

To migrate a legacy bundled plugin, set its folder-matching lowercase id and API v1 manifest fields, declare all scripts and sounds using safe relative paths, and move hook, listener, and timer lifecycle work to ctx.api. Check the plugin migration notes for the step-by-step checklist. A future breaking API needs compatible runtime version handling, a new SDK type file and starter, and a payload-by-payload migration guide. Third-party installation still requires reviewed permissions, isolation, resource limits, and failure recovery.

The plugin security model records the trust boundary and release gates for community-authored plugins, including capability prompts, isolation, multiplayer validation, and safe map dependency handling.

Plugin controls

Declare bindings in the manifest's controls object. Each entry needs a globally unique plugin input id, a browser KeyboardEvent.code, and a player-facing label. Control ids must be unique across every registered plugin because plugins share player.input; the runtime skips a plugin with a duplicate id, and the author preflight reports the conflict. The plugin library shows the label and key. While that plugin is enabled, the input is available as a boolean on player.input; for example, an entry named special bound to KeyQ is read as player.input.special from player.update. The value stays true while the key or touch button is held and clears on release or when the plugin is disabled. Touch-first gameplay shows labeled buttons for declared plugin controls. Core movement input ids (left, right, up, down, jump, shift, and space) are reserved and rejected by runtime discovery and author preflight. The action ids attack, heal, dash, and superDash are also reserved for built-in plugin actions, and are intentionally declared by the Hollow Knight plugin. In Mechanics, the Player Action Input trigger lists controls from enabled plugins; it runs the linked Event once per press, including touch presses. These plugin-control Events are local in hosted rooms, so use a supported host-validated trigger path for shared changes.

"controls": {
  "special": { "key": "KeyQ", "label": "Special" }
}

Plugin API v1 hook reference

Hooks execute synchronously on the game thread. Return the same data object after changing fields; hook return objects are merged into it. Lower priority numbers run earlier. Keep per-player state on namespaced player fields and do not retain canvas contexts or event payloads after the callback. world.queryNear() is a broadphase query whose result array may be reused by the next query; copy it with .slice() before querying again or invoking a hook/Event that can query the world. If one hook throws on three consecutive calls, Parkoreen removes that hook and releases its registered cleanup; a successful call resets the failure count. The plugin card reports removed hooks and their last error. Fix the source, bump the plugin version if it is bundled, and reload to retry. This prevents a repeatedly throwing callback from running every frame, but it does not sandbox trusted plugin code or stop a synchronous infinite loop.

HookPayloadBehavior
game.ended{ player, world, elapsedMs, wasTestMode }Runs once after endpoint completion and Code runtime cleanup, before the results callback. Use this for plugin-local completion UI; it does not make guest completion authoritative.
game.sceneLoaded{ player, world, mapId, previousMapName, mapName }Runs after a solo Mechanics scene transition loads the destination and initializes its plugins. Use it to refresh map-scoped plugin state.
player.init{ player, world }Runs when the local player object is created. Add namespaced state here.
player.update{ player, world, audioManager, deltaTime, skipPhysics }Runs each gameplay update. Set skipPhysics = true only when the plugin supplies velocity; the engine still applies collision movement.
player.jump{ player, canJump }Offers an alternate jump when the base game cannot jump. Set didJump = true to consume the jump and emit player.jumped.
player.jumped{ player, world, wasGrounded, source }Notification after a successful jump; source is core or plugin.
player.land{ player, world, surface }Notification on the transition from airborne to a solid floor collision. It does not fire for respawns, jump-limit changes, or other jump resets.
player.damage{ player, source, world, preventDefault }Set preventDefault = true to handle the damage instead of the base death behavior.
player.died{ player, world, source }Notification after a fatal transition. It runs once, immediately before the engine's automatic respawn step; source identifies the hazard, void, or gameplay action when available.
player.checkpoint{ player, world, checkpoint }Runs on each update while the player overlaps a checkpoint, and when a mechanics action sets one. Plugins can use this to refresh checkpoint-dependent state.
player.respawn{ player, world }Runs after the local player is respawned. Reset transient plugin state here.
input.keydown / input.keyup{ key, player }Local keyboard code and player; keyboard events are not delivered while a text input is focused.
input.update{ player, keys, layout }Runs while core input is mapped to player controls. keys is the current key-state object.
button.pressed{ button, player, world }Notification after a map button is activated.
render.camera{ camera, player, world, offsetX, offsetY }Runs before the gameplay scene is drawn. Add frame-local screen-pixel offsets; the engine clamps each axis to ±24 px and does not modify live camera tracking.
render.player{ ctx, player, camera, world }Runs just after the local player is drawn, so plugin effects appear over the player.
render.hud{ ctx, canvas, player, world, xOffset, yOffset }Draw local HUD elements in canvas coordinates.
render.soulStatue{ ctx, screenX, screenY, width, height, obj, handled }Set handled = true after drawing to replace the built-in Soul Statue appearance.
