🧩 Mechanics

Connect gameplay triggers to reusable Events, conditions, variables, and actions without writing a plugin.

Open the editor’s Mechanics panel to create three kinds of blocks: Triggers start a flow, Events contain ordered actions, and Variables hold values or Lists. Select Flow map to see and follow their links. Trigger and Event cards link to connected Events and referenced Variables; Event cards also link to Triggers they enable or disable, while Trigger cards show which Events change them. Variable cards link back to their using triggers and Events. Give blocks clear names, then use Flow map and the validation panel to find missing links, unreachable Events, recursive paths, and invalid values. Reachability includes Events behind disabled Triggers when a reachable Event can enable them.

Build a first game mode

  1. Choose a starter under Templates, such as Timed Round, Tag, Hide And Seek, Player Inventory, or Switch And Door. A template creates linked blocks with fresh IDs; it is a starting point you can edit or remove.
  2. Open Flow map. Follow the trigger’s connection to its Event, then follow any branch or timer links. Rename blocks so the flow reads like your rules.
  3. Use the Event editor to add, configure, and reorder actions. Add branches for decisions, timers for delayed work, and Run Event to reuse a flow.
  4. Use Test Game for solo iteration. The Mechanics dashboard records author-facing runtime errors and lets you jump to the affected block.
  5. For multiplayer rules, host a room and try it with another player. Hosted behavior depends on the trigger and action: some checks run locally, while supported shared changes are host-validated and synchronized. The editor describes behavior on the selected trigger or action.

Object contact triggers include begin and end edges. Disabling an edge trigger keeps its condition state current, so enabling it while a key, contact, or matching condition is already active does not create a false new edge. Game Starts, Game Ends, death, and room lifecycle events have defined one-time behavior for their lifecycle. A solo menu that pauses the simulation also freezes Repeat, Timer, timed-fall, and timed-jump clocks. Trigger help text explains whether a hosted-room event is local or handled by the host. Guest position samples are client-reported; overlap checks improve consistency but are not server-simulated physics.

Events and actions

An Event runs its enabled actions in order. Branch actions route to linked Events; Run Event reuses a linked flow. Timers can schedule an Event later, and menus, choices, and dialogue can pause the local player while the player responds. The action catalog is grouped here by what each action changes:

Action fields validate their target and bounds; linked actions use Event pickers. Integer variables and typed List items accept only safely representable whole numbers; Add and Calculate reject values that would lose integer precision, and Calculate also rejects division by zero. Select an action in the editor to see its specific limits and multiplayer behavior. Runtime limits also bound chain depth, action count, timers, Lists, temporary objects, and dialog content so a flow cannot grow without limit. For supported hosted trigger flows, the host replays the trigger-linked Event in order, evaluates declarative branches, and records enabled choice routes when it reaches a Show Choices or Show Menu action. A guest's local selection is accepted for host replay only when the Worker verifies it is declared by that parent and the host has a matching pending route.

Branch on Object Health compares temporary health initialized by Set Object Health or Damage Object. Use it to route enemy phases or health-gated doors; the Flow map shows both routes. Supported shared triggers evaluate from the room host's health state, while local-only triggers remain local.

Define up to 32 named clips on each object sprite sheet by setting a name, frame range, speed, and loop mode. Play Object Sprite Animation can use a named clip or a one-off frame range; a one-shot can start an optional completion Event and hold on its last frame. In a hosted room, the room host runs that completion Event once; session reset restores the authored automatic animation.

Set Draw Layer Visibility can show or hide an authored draw layer during the current session. It changes rendering only; collision and object behavior stay active. In hosted rooms, the host validates and synchronizes visibility overrides. Reset restores every layer's authored default.

Set Object Draw Layer can move a map object between authored layers during play without changing its position or collision. Collidable objects cannot move to parallax layers. The action saves with its Event, synchronizes through host-validated state in rooms, and returns to the map's authored layer on reset.

Events can also include Python code for advanced rules. Its versioned parkoreen context has bounded snapshots and supported state operations; it is not unrestricted access to the game engine. Keep loops and chains within the limits shown by validation. Prefer declarative actions when they express the rule clearly.

Variables and Lists

  • Map scope shares one value or List in that map session. Campaign scope shares a value or List across maps that use the same Campaign Key and saves automatically for solo play in this browser account (or on this device while signed out). Campaign saves do not sync to other devices and are not read or written in Test runs or hosted rooms. Player scope keeps a separate value or List for each player.
  • Scalar values support text, integer, float, and boolean types. Lists hold bounded, typed items and support add, remove, and contains branches.
  • Some values can opt into local browser saves for solo play. These saves do not sync between devices; test runs and hosted rooms remain temporary for these options.
  • Player scope separates state but does not make it secret in a hosted room.

Save, reset, and compatibility

Triggers, Events, variables, and their links are part of map data and travel with normal map saves and .pkrn export/import. Runtime changes are session state: reset restores authored object, trigger, camera, and tilemap settings. Older editors preserve mechanic records they do not understand when saving unrelated edits, but an older runtime cannot execute unsupported types.

Mechanics failures appear in the dashboard with the Event and action location. During Test Game, Parkoreen shows a brief, rate-limited notice; hosted player sessions do not show author diagnostics.
