Changelog

Notable changes to Parkoreen. Current summarizes the present build; numbered v0.x sections retain historical release milestones (see reference at the bottom).

Entries are grouped from git log (newest first within each section).

Current — Unreleased

Development on origin/next (after the v0.3 merge); not yet cut as a numbered v1.x release.

Mechanics Editor

  • List action diagnostics: malformed imported List actions now report invalid typed items and unsupported Player List targets; the runtime no longer silently changes an unknown target to the triggering player.
  • Full List diagnostics: Add List Item now reports a rate-limited author error when the List has reached its 100-item limit instead of failing silently.
  • Declarative List additions: Add List Item now commits through the shared List update path, so Map, Campaign, and Player Lists persist and synchronize with the same behavior as removal and clearing.
  • Host UI replay ordering: multiplayer host replay stops at Dialogue, Choices, and Menu actions. It records declared choice routes first, and later shared actions wait until the local UI pause or selection Event completes.
  • Nested terminal path analysis: reachability, execution-limit warnings, and timer-cycle analysis now stop after a Run Event that always transitions or restarts, and after a branch only when every possible route ends the shared Event chain.
  • Terminal path diagnostics: reachability, execution-limit warnings, and timer-cycle analysis now stop at direct scene transitions and restarts, matching runtime Event order.
  • Terminal action reachability: Mechanics reachability now stops after direct scene transitions and restarts, so links in actions the runtime skips are not reported as reachable.
  • Trigger-aware reachability: Events that enable a disabled Trigger now make that Trigger's linked Event potentially reachable in dashboard analysis.
  • Flow map edge direction: links now curve according to their source and target columns, including Event-to-Trigger state changes; same-column Event routes pass around the cards.
  • Trigger state navigation: Event cards and the Flow map link to Triggers targeted by Set Trigger Enabled, while Trigger cards link back to those Events; link labels show whether the action enables or disables the Trigger.
  • Variable navigation from blocks: trigger and Event cards link directly to referenced Variables, and Variable cards link back to their consuming triggers and Events, including List and inventory actions.
  • Flow link consistency: the full Mechanics Flow map, block cards, reachability checks, synchronous path warnings, and timer-cycle analysis now read Event routes from the same action-link catalog while keeping delayed routes distinct. Inventory consumption links are labeled by their used and missing-item outcomes.
  • Hosted choice routes: for supported triggers, the host replays the linked declarative Event in order and records options reached at Show Choices or Show Menu. The Worker checks that the selected Event is declared by its parent, and the host accepts it only against that pending route record before executing shared actions.
  • Branch on Object Health: compare initialized temporary health on a selected or touched object, then route to a true or optional false Event. Comparison bounds, Event targets, recursion, Flow map links, and hosted shared-state handling are included.
  • Named object animation clips: sprite-sheet objects can define up to 32 validated frame-range clips with a speed and loop mode, then reuse them from Play Object Sprite Animation actions. One-shot clips can use the existing completion Event route.
  • Sprite animation completion Events: one-shot object animations can run a linked Event when their final frame completes. The Flow map and unreachable-Event analysis include the delayed route, hosted rooms run it once on the host, and a solo pause freezes its animation clock.
  • Calculate Number Variable: Events can add, subtract, multiply, or divide integer and float variables for the triggering, touched, or all live players. Division by zero and fractional or unsafe integer results are reported without changing the value.
  • Disabled trigger edge tracking: disabled key, player-stat, variable-condition, and player-action triggers now keep relevant state current, preventing a false edge when a trigger is enabled during an already active condition.
  • Per-trigger fall edges and pause clocks: each Fall action trigger tracks its own falling transition, so multiple flows can react to one fall. Pausing a solo menu now freezes the elapsed clocks for Fall for Time and Jump for Time inputs.
  • Mechanics Guide: added a dedicated walkthrough of trigger types, linked Events, actions, variables, reusable templates, save/reset behavior, and hosted-room limits.
  • Plugin query lifetime: the API v1 type declarations and Guide explain that world.queryNear() may reuse its result array, so plugins must copy candidates before nested queries or hook dispatch.
  • Mechanics mode-building guide: the Guide now walks creators through adding and extending the Tag Game and Hide And Seek templates, inspecting their linked Events, and checking multi-player behavior in a hosted room.
  • Nested interaction scans: Hollow Knight slash, checkpoint/endpoint, and immediate button checks preserve their nearby-object candidates while plugin hooks run Events that query the world.
  • Hollow Knight hit-scan stability: down-slash attack candidates are copied before plugin hooks run, so a Mechanics Event's nested world query cannot replace the live nearby-object results and skip later pogo surfaces.
  • Hollow Knight pogo contact: solid blocks and tilemap cells now pogo only when the projected feet sweep reaches the top surface, then place the player on the contact plane before rebounding. Fully solid polygon colliders use the expanded player contact plane from normal physics. The long down-slash hitbox still hits enemies and Soul Statues, but no longer causes an early midair platform bounce.
  • Session camera actions: Mechanics Events can switch local camera follow axes and apply custom bounds, remove bounds, or restore Map Config bounds for room transitions; the authored settings return on session reset.
  • Mechanics snapshot isolation: World serialization now copies and normalizes trigger, Event, and variable records so Test Game snapshots and map save objects do not alias the live mechanics data.
  • Tilemap trigger validation: editor validation, local contact, and hosted contact/rearming now agree on one-way ramps and polygon surfaces, so valid filtered triggers save and rearm consistently.
  • Strict variable editing: integer defaults, List items, and explicit List lengths no longer silently truncate fractional input or replace invalid lengths by inference. Invalid and blank values remain visible until the editor rejects them, and zero renders as zero. Legacy Lists with no length field still infer it from their items.
  • Player sprite action states: character sprite sheets can optionally define Attack, Hurt, and Dash rows for Hollow Knight nail swings and dashes, and Health damage stun. Attack plays once; Hurt and Dash loop while active. Maps with only the four locomotion rows keep their existing behavior.
  • Extended tilemap animation cycles: animate painted cells with up to eight built-in texture or tile-atlas frames at 1–12 FPS. Duplicate frames can hold a texture longer, and the 2,048-cell animation budget is unchanged.
  • Mechanics object health: Set Object Health and Damage Object add temporary per-object health, defeat disablement, optional defeat Events, and host-synchronized health snapshots for supported shared triggers.
  • Basic HK Enemy template: wire a selected object to nail-hit damage and a defeat Event, with optional timed patrol that turns sprite-sheet artwork at each endpoint, and player contact damage. Hosted patrol motion is host-synchronized; nail-hit health and contact damage remain client-local.
  • Player Attacks Object trigger: connect Hollow Knight nail hits to Mechanics Events, once per target per swing, with object and slash-direction context. The hit hook is also included in the API v1 plugin types; hosted-room attacks remain local.
  • Monarch Wing strength: configure the double-jump force per map from 0.5× to 2× the map's normal jump force; the default now matches the plugin's declared setting.
  • Hollow Knight jump-force alignment: wall jumps, Monarch Wings, and pogo use the core engine's default upward force when saved physics data is invalid, so abilities keep the intended jump strength.
  • Hollow Knight movement physics alignment: wall clings and rebounds now use the core map gravity and terminal-fall rules, so custom physics and default maps behave consistently with pogo's projected fall step.
  • Plugin preflight resource limits: declared files over 64 MiB, combined manifest and asset data over 128 MiB, and packages above 256 entries are rejected before JavaScript syntax parsing; preflight now applies the packager's documented bounds.
  • Mechanics export normalization: .pkrn serialization now applies the shared map-data normalizer, keeping exported Events and repaired IDs consistent with the shared load migration.
  • Hollow Knight pogo broadphase: down-slash searches now include the full projected feet sweep for the next bounded fall step, allowing fast falls to detect thin platforms at the end of that step.
  • High-speed Hollow Knight pogo resolution: when a fast fall leaves the player's feet slightly inside a solid pogo surface, the plugin lifts the player above the bounded contact plane before applying the bounce. This prevents the following collision pass from treating the surface as a ceiling and clearing the rebound velocity.
  • Forward-compatible Mechanics records: older editor versions now show unknown action and trigger types instead of replacing them with a supported default. Action fields survive Event edits and reordering; trigger config and its Event link survive trigger saves; unknown scalar and List value types stay intact through unrelated variable edits.
  • Python player and tilemap APIs: Event scripts can request bounded pages of client-visible player snapshots, inspect or mutate Player variables and Lists by live player id, and read native tilemap summaries/cell snapshots, including collision, polygon, texture, atlas-frame, and animation metadata. Player snapshots omit account usernames and are not server-authoritative; only the room host publishes player-state writes. Tilemap behavior changes validate against existing grid-aligned cells, atlas image data stays private, and guests cannot write shared cells.
  • Plugin manifest contract: runtime discovery now applies the same API v1 constraints as author preflight for script extensions, feature flags, object guards, and optional metadata. The JSON schema matches the runtime rules, so an invalid manifest is rejected consistently.
  • Plugin API v2 draft: gameplay request variants now have closed, action-specific payloads, and host results have method-specific shapes. Map snapshots page at 64 objects per response; player snapshots use a separately granted capability, opaque room-session ids, and no account identifiers. Plugin ids accept Parkoreen's lowercase underscore syntax, and stored values are limited to 32 KiB of UTF-8 JSON so response envelopes fit inside the message-size limit. A future broker must correlate each response id to its request method; the protocol remains a non-runtime draft.
  • Capsule colliders: ground blocks can use a solid capsule rounded along their longer axis. Movement collision, the tester overlay, map import/export, Mechanics object-contact triggers, and host-validated room contact checks recognize capsule geometry.
  • Hollow Knight pogo rebound flare: a brief configurable-color upward burst now distinguishes the rebound from the nail-contact sparks; it follows the impact-effects setting and does not change movement.
  • Animated nail slash tip: a glowing highlight travels along the configured slash arc during each swing, adding directional motion while remaining controlled by Nail Slash Effects.
  • Inventory equipment actions: equip or unequip a named JSON card in a Player List with one equipped item per slot, then branch Events on the equipped state. Hosted Events synchronize the changed Player List through the room host.
  • Mechanics Restart Scene: solo Play and Test Events can restart the active scene from its saved checkpoint, Spawn Point, or default start. Scene-local Mechanics state resets and Game Starts runs again; multiplayer restart is not available.
  • Inventory item use: consume one card by name and slot, decrementing stacks or removing the last use, then route to success or optional missing-item Events. Item effects can be composed from existing variable, health, message, and map actions.
  • Inventory card validation: malformed optional count, icon, description, and equipped fields no longer behave like valid item cards; equipping a repeated name/slot equips just one matching card.
  • Transactional item use: before consuming a card, the runtime verifies the required success Event and optional failure Event are enabled, non-recursive from the active Event chain, and within execution limits.
  • Unsupported action diagnostics: imported Events with malformed or unknown action records now appear in the map's mechanics error history, including the source Event and action position.
  • Plugin compatibility diagnostics: the plugin library identifies map-required plugin ids absent from the reviewed local library and reports registered plugins that fail during loading or initialization. Map settings remain preserved, and importing a map never installs or executes plugin code.
  • Solid custom polygons: custom convex ground colliders can now be one-way surfaces or fully solid from the sides and underside. The mode is saved with the map and carried through .pkrn exports.
  • Custom ground polygons: author a convex collider with 3–12 normalized vertex pairs on a ground block. Invalid, concave, self-intersecting, degenerate, and out-of-range geometry is rejected; the polygon lands from above, follows its top surface, passes players through from below, and round-trips through map and .pkrn saves.
  • Ground ramps: choose rising left-to-right or right-to-left triangular colliders for ground blocks. Players land from above, follow the slope while walking, jump from it, and drop through with Down + Jump. The tester touchbox overlay shows the triangle, and shape data survives map and .pkrn saves.
  • Tilemap polygon colliders: configure a 3–12 point convex shape for solid or one-way tile cells. Choose one-way top-surface or full-solid collision; map saves and .pkrn files preserve the points, and local and hosted tilemap contact checks test the actual polygon. The tester touchbox overlay outlines visible custom tile colliders.
  • Hollow Knight pogo contact: downward slashes can pogo from a solid platform on the first contact frame even when a fast fall crosses the surface by a few pixels; hits from below remain ineligible.
  • Pogo world-coordinate fix: down-slash contact now uses the ground collider's world-space feet position without adding the player's Y position twice, preserving pogo hits throughout tall maps.
  • Mechanics Show Menu: Events can open a centered, titled menu with 1–8 linked options. Escape and backdrop clicks close it or run an optional cancel Event; the local player pauses while it is open, and the options remain scrollable on small screens.
  • Expanded game menus: Mechanics choice prompts now support 2–8 linked options. The option list scrolls within a bounded height, keeping larger menus usable on small screens.
  • Event execution-limit warnings: the Mechanics dashboard analyzes linked synchronous Event paths and warns when their nesting depth or combined action count can exceed runtime limits. Warnings appear on Event cards and Flow map nodes before Test Game.
  • Consistent mechanics map migration: the main and dashboard import/export pages now load the shared mechanics-data normalizer before map deserialization, matching the editor's legacy Event and ID repair rules across app entry points.
  • Event-link diagnostics: missing or disabled Events linked from triggers and timers, plus recursive and over-limit action links, now appear in the per-map runtime error history. Select a reported trigger or Event-link error to edit the originating block. Item-use actions check success and optional failure routes before consuming inventory, so a broken route is visible and does not remove an item.
  • Custom tilemap atlases: upload a bounded PNG, JPEG, or WebP atlas per tilemap layer, select and preview a frame, and paint it into 32 px cells. Atlas frames can animate in cycles of up to eight frames at 1–12 FPS. Atlas image data is bounded across the map and survives save/load and .pkrn media-file round-trips; collision remains an independent cell behavior.
  • Repair broken List references: List items offer variable references only when an eligible scalar Map variable exists. A deleted or otherwise ineligible reference shows an explicit replacement prompt, so choosing a valid replacement updates the saved item directly.
  • Animated tilemap textures: paint cells that cycle through up to eight built-in texture frames at 1–12 FPS. Animation data survives save/load and .pkrn round-trips, leaves collision unchanged, and is capped at 2,048 cells per map.
  • Hollow Knight pogo feedback: down-slash impacts add a brief lateral nail-shard burst at the actual collider contact height, including curved surfaces. It uses the configured nail-effect color and follows the impact-effects toggle without changing hit detection or bounce physics.
  • Plugin authoring starter: the API v1 example now declares and loads its sample SVG through ctx.api.getAssetUrl(), demonstrating the full manifest-to-render path for plugin-owned assets.
  • Hollow Knight Focus completion effect: a successful heal releases a short pulse and radial motes in the configured heal color; cancelled or ineffective Focus attempts do not trigger the burst.
  • Button Save Point template: bind a uniquely named Button to a Checkpoint object; pressing it sets the local player's respawn point. Enable Remember Latest Checkpoint in Map Config to resume there on a later solo visit in the same browser.
  • Pause Menu template: generate an Escape-key Resume/Restart menu that pauses solo simulation and Mechanics timers, with an optional Button-object trigger for touch-first play. The editor prevents duplicate Escape menus, and Restart Scene resets the active scene and runs its Game Starts events again.
  • Title Menu template: add a Game Starts Welcome screen with a touch-friendly Start option. Solo simulation waits at the title screen, and the editor prevents duplicate startup menus.
  • Python movement API: event scripts can read player velocity, grounded/dead state, and remaining jumps, and use parkoreen.set_player_velocity(vx, vy) for bounded local movement control.
  • Set Gravity and Set Jump Force: Mechanics can temporarily set gravity from 0 to 5 and jump force from -100 to -0.1, or restore their Map Config values. Core and Hollow Knight movement share both values, hosted play synchronizes them from the host, and session reset restores the saved map settings.
  • Imported physics action validation: invalid modes and out-of-range gravity or jump-force values now appear in the Mechanics runtime error history instead of silently being skipped.
  • Broken trigger targets: Player Enter/Leave Zone, Player Touches Object, and Player Touches Tilemap now report missing or disabled targets once until repaired, instead of repeating the same runtime error every frame.
  • Hollow Knight damage feedback: when the HP plugin confirms lost health, a short directional flash and shard burst marks the hit. Invincible or canceled damage does not show the effect.
  • Set Player Speed: Mechanics can temporarily change horizontal movement speed from 0.1 to 100 pixels per tick or restore Map Config speed. The setting applies to core movement and Hollow Knight wall movement, syncs from the host, and resets with the play session.
  • Set Movement Control: Mechanics can temporarily change horizontal acceleration, air control, or terminal fall speed within their Map Config bounds; hosted rooms synchronize the settings from the host, and reset restores the saved values.
  • Set Object Sprite Frame: Mechanics Events can hold a sprite-sheet object on a selected frame for state changes such as alert, attack, or defeated, then resume its automatic animation. The host synchronizes the frame with the room.
  • Sprite frame authoring validation: an empty frame field no longer silently selects frame zero, and malformed imported sprite-frame actions report the object or frame requirement in Mechanics runtime history.
  • Set Object Opacity: Mechanics can fade a map object from 0 to 1 or restore its saved opacity without changing its collision. Hosted rooms sync the host's validated override; reset restores the authored appearance.
  • Play Object Sprite Animation: Events can play a bounded frame range from an object's row-major sprite sheet at 1–30 FPS, loop it, or hold its last frame. Animation start time and settings synchronize from the room host; reset restores the sheet's automatic animation.
  • Sprite-sheet frame validation: Object sheets now reject frame counts beyond decoded image capacity. Player sheets validate every configured animation row and frame count against the image after dimension changes, avoiding states that silently clamp to another row or frame.
  • Tilemap ramps: paint one-way ramps that rise left or right; Player Touches Tilemap treats both directions as one-way surfaces, and Set Tilemap Cell Behavior can change cells to either ramp in solo and hosted play.
  • Set Tilemap Cell Behavior: change a fixed or touched cell to solid, one-way, either ramp, damage, or decorative during play. Changes reset with the session and are synchronized from the host in multiplayer.
  • Player Touches Tilemap: run an Event when a player enters collidable cells on a selected tilemap, with optional solid, one-way (including ramps), or damage-cell filters. Hosted rooms check contact against saved tile data and recent player positions.
  • Hosted button events: shared Mechanics events triggered by a button require a recent guest position inside that button, and the host confirms the button identity before replaying its shared actions.
  • Timer-cycle diagnostics: the dashboard marks event cycles that cross a Start Timer action, including in the Flow map. Intentional loops remain supported; timer events stop after 10,000 fires per map session.

Editor & maps

  • Sprite-sheet metadata validation: imported object sheets reject fractional frame dimensions and frame counts and refuse ranges beyond the decoded image; player sheets reject malformed explicit animation rows/counts and ranges beyond the decoded image rather than rounding, silently defaulting, or dropping those states. The settings panels report image-bound mismatches for repair, while legacy player sheets that omit optional fields keep their defaults.
  • Native Tilemap Brush: paint compact 32×32 px solid, one-way, left- and right-rising ramp, damage, and decorative cells on a selected draw layer; choose texture/color/opacity, erase cells, and preserve tilemaps through map saves and .pkrn import/export. Mechanics can temporarily change cell behavior through a fixed coordinate or tile-contact event.
  • Player Dies mechanics trigger: run an Event once at the actual death transition before automatic respawn, with the hazard or gameplay source in Python context; guest deaths stay local.
  • Game Ends mechanics trigger: run a local Event once after endpoint completion requirements are met; Python context includes elapsed milliseconds and test-run status.
  • Hollow Knight down-slash pogo: solid platforms use their actual collider top for pogo eligibility, including round colliders; slash checks use collider geometry, while spikes and Soul Statues retain their impact behavior.
  • Player Lands mechanics trigger: run an Event after a real airborne-to-ground transition, with landing surface id/name in Python event context. Guest landings remain local in hosted rooms.
  • Player Jumps mechanics trigger: run an Event after a successful core or plugin jump, with grounded/air-jump and jump-source values in Python event context. Guest jumps remain local in hosted rooms.
  • Python map-object API: Event scripts can page through bounded read-only object snapshots and request validated object enable/disable or position changes. Hosted guests cannot write shared objects.
  • Plugin preview file watching: the localhost preview watches the selected plugin folder and reloads the editor when its manifest, script, or asset files change.
  • Hollow Knight pogo safety: the runtime bounds saved pogo strength and requires a finite, upward world jump force, so malformed imported settings cannot poison the player's velocity.
  • Hollow Knight attack tuning: choose Base or Quick Slash in Map Config. Camera follow smoothing is managed by the general map camera controls, so the plugin no longer advertises unused camera settings.
  • Hollow Knight tuning: Map Config now exposes pogo bounce strength and camera shake controls for nail hits, landings, and Super Dash impacts. Values are bounded and saved with each map.
  • Local plugin preview token: each dev server run prints a random token required to discover unregistered plugins, fetch their files, and connect the reload stream. This blocks a web page from silently starting a localhost preview; preview code still runs with trusted page access.
  • Reorder mechanics actions: Event actions now have up/down controls. Reordering keeps unsaved field values and the runtime still executes actions from top to bottom.
  • Mechanics dialogue action: events can show a speaker and up to 12 pages in a touch-friendly dialogue panel. The local player pauses while it is open, Enter/Space or the button advances, and event Python resumes after dismissal; the editor requires dialogue-yielding flows to end the event chain.
  • Mechanics choice action: events can present 2–4 labeled options that run enabled linked events. The selected event completes before the parent event’s Python resumes. The editor validates labels and recursive paths, and the Flow map displays each choice link. Prompt and selection are local; shared multiplayer state still needs a host-authoritative trigger flow.
  • Mechanics scene transitions: events can load another saved map in solo Play or Test, including from Game Ends to continue a level sequence. Transitions place the player at its saved checkpoint or spawn, reset scene-local state, start destination Game Starts events, end the current event chain, and remain disabled in multiplayer rooms. Failed destination loads preserve the normal completion screen.
  • Player Health Changed trigger: mechanics can react to numeric health increases/decreases, retain a baseline per player, and expose before/after/delta values through Python event context. Guest-triggered shared requests are rejected because health is client-reported.
  • Player Respawns trigger: mechanics events can run after checkpoint placement and all plugin respawn hooks finish. It stays local to each player's client in hosted rooms.
  • Player-scoped mechanics Lists: Lists can hold separate typed collections for each live player, and Event actions can mutate or branch on the triggering or touched player's items. The Python List API and room host snapshots also support Player Lists; solo local saves remain opt-in. Hosted snapshots are visible to every client, so Player scope does not make values secret.
  • Show List Panel action: Events can open a touch-friendly, scrollable local panel for a Map or Player List. It refreshes while gameplay continues, closes from its button or Escape, and can be bound to a key or button trigger for a basic inventory or collection view.
  • Player Inventory template: Adds an empty Player List, an I-key opener, and a live inventory panel. Optionally bind a map object to collect it into the List on contact; Button-object touch activation and local solo saves are also configurable.
  • Object anchored teleports: Mechanics events can place the player centered above an enabled map object and clear velocity, alongside the existing coordinate teleport action.
  • Bounded player movement actions: Coordinate teleports and velocity components now use matching editor and runtime limits.
  • Hollow Knight impact camera feedback: nail hits, landings, and Super Dash wall impacts can add a short, configurable shake. The new render.camera plugin hook supplies frame-local offsets with a strict pixel limit; it does not change gameplay camera tracking.
  • High-speed down-slash pogo: the Hollow Knight plugin checks the player's next bounded downward physics step against the platform surface, so fast falls cannot pass through thin pogo surfaces between updates. Solid-platform pogo also requires non-upward movement, so a rising player cannot bounce from the underside of a one-way platform.
  • Object Stamps: save selected map objects as a reusable map asset, then place copies with fresh object IDs. Stamps persist in map saves and .pkrn files, and can now move between maps through validated, data-only .pkrstamp files (64 objects, 2 MiB). Portal links between copied objects are remapped together; links to objects outside the group and mechanics blocks are not included.
  • Temporary mechanics objects: events can spawn copies of eligible authored objects near a player, remove copies by tag, and expire copies after an optional lifetime. Maps cap these runtime instances at 64, touch triggers can target a spawned template, and hosted rooms synchronize validated instance data from the host.
  • Platform movement tuning: map physics can use bounded horizontal acceleration and braking, adjustable air control, and an optional terminal fall speed, while old maps retain their instant-start movement and gravity-scaled falling.
  • Plugin asset versioning: declared plugin scripts and sounds load with the plugin release version in their URLs, preventing stale browser or service-worker caches after an asset update.
  • Mechanics save migration: one shared normalizer is used by map load, .pkrn import, the editor, and runtime. It merges distinct legacy actions records into events, preferring canonical event records when IDs overlap.
  • Room event routing: the multiplayer worker applies the same canonical-first event ID lookup, so older linked events are not rejected when a map also contains newer event records.
  • Hosted contact checks: the Worker checks zone transitions, object and button overlap, and player-to-player contact using recent client-reported positions, derives the touched player id, and suppresses repeat contact events until separation. Positions are not server-simulated, so this remains a trusted-playtesting feature rather than cheat-resistant gameplay.
  • Mechanics Flow map: switch from block cards to a connected view of triggers, events, and variables. It draws trigger links, event calls and branches, timers, and variable use; select a node to edit its block.
  • Local progress saves: maps can remember a player's latest checkpoint, and mechanics variables can opt into map or per-player persistence. Saves are scoped to the map and current account (or browser when signed out) and remain local to that browser.
  • Persistent mechanic object states: Set Object Enabled actions can remember an object's enabled state between solo visits on the same browser. Test runs and hosted rooms stay temporary.
  • Mechanics Lists: Map and Player scoped Lists support typed add/remove actions and contains branches, with a 100-item limit, optional browser-local solo saves, and host-authoritative room snapshots. Player scope keeps separate state per player, while hosted values are sent to every client.
  • Behind-player layer persistence: layer 0 now survives object construction and remains layer 0 in render caches, gameplay, sorting, and the object inspector.
  • Camera controls: choose two-axis, horizontal, or vertical following, and optionally define a world-space rectangle that clamps the camera during gameplay and testing. Existing maps retain the two-axis unbounded behavior; smaller bounds center within the viewport.
  • All Spike map import: `.pkrn` deserialization now accepts the All Spike touchbox mode for world settings and individual spike objects, preserving the saved hazard behavior on import.
  • Saw blade multi-select: bulk-edit popup now includes Width (blocks), Height (blocks), and Damage Amount alongside Spin Direction and Spin Speed, so multiple blades can be resized and configured together.

  • Player Touches Object shapes: mechanics triggers can detect a box, a circle, or a capsule centered on the selected object; rounded shapes use a radius equal to half the shorter side. This is trigger overlap geometry and does not change solid platform collision.
  • Room lifecycle triggers: Player Joins Room and Player Leaves Room run linked events once on the host for each guest arrival or departure while the host remains connected, with the player's id, name, and username in the event context.
